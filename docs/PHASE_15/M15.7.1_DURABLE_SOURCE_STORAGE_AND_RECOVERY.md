# M15.7.1 — Durable Source Storage & Recovery

**Status:** IMPLEMENTED  
**Date:** 2026-09-22  
**Branch:** main  
**Depends on:** M15.7 (Ingestion Reliability, Dead-Letter & Recovery)

---

## Overview

M15.7.1 implements durable source file storage for the LINKRA ingestion pipeline, enabling automatic recovery of original source files during job retry — even when the local working copy has been lost (container restart, disk cleanup, server migration).

This closes the remaining reliability gap identified in M15.7 where `SOURCE_FILE_MISSING` was immediately classified as `PERMANENT_FAILURE` with no recovery path.

---

## Architecture

```
INGESTION SOURCE (upload)
    ↓
DURABLE SOURCE STORAGE  ← NEW (M15.7.1)
    ↓
IngestionJob stores durable source reference + SHA-256 checksum
    ↓
Normal ingestion pipeline
    ↓
Failure
    ↓
Retry
    ↓
Verify durable source  ← NEW (restore_source_for_job)
    ↓
Restore local working copy
    ↓
Verify SHA-256 checksum integrity
    ↓
ONLY THEN → cleanup_job_outputs()  ← CRITICAL ORDERING FIX
    ↓
Full idempotent reprocessing
    ↓
COMPLETED / COMPLETED_PARTIAL
```

---

## Critical Bug Fix: Retry Ordering

**Before (M15.7):**
```
Lock job → Check local file → cleanup_job_outputs() → Execute pipeline
```

If the local file was missing, `cleanup_job_outputs()` had already destroyed partial outputs, leaving the job in a worse state.

**After (M15.7.1):**
```
Lock job → Validate retry → Verify durable source → Restore local copy → Verify SHA-256
    → ONLY THEN → cleanup_job_outputs() → Execute pipeline
```

If source restoration fails, existing partial outputs are **preserved**.

## Storage Abstraction

### Provider Interface: `SourceStorage`

Location: `backend/app/ingestion/storage.py`

Abstract methods:
- `upload_source(key, data, content_type)` — Upload raw bytes
- `source_exists(key)` — Check existence
- `get_source_metadata(key)` — Return size/content_type
- `download_source(key)` — Download raw bytes
- `delete_source(key)` — Remove object

### Providers

| Provider | Env Var | Suitable For |
|----------|---------|--------------|
| `LocalPersistentStorageProvider` | `SOURCE_STORAGE_PROVIDER=local` (default) | Development, testing, single-server |
| `SupabaseStorageProvider` | `SOURCE_STORAGE_PROVIDER=supabase` | Production, multi-server |

### Provider Selection

```
SOURCE_STORAGE_PROVIDER=local     → storage/ingestion/  (persistent, not /tmp)
SOURCE_STORAGE_PROVIDER=supabase  → Supabase Storage bucket
```

If Supabase credentials are missing, falls back to local provider with a warning.

## Storage Key Format

```
ingestion/{job_id}/source/{sanitized_filename}
```

Example: `ingestion/3fa85f64-5717-4562-b3fc-2c963f66afa6/source/fir_report.pdf`

## Database Schema (M15.7.1)

Migration: `m1571_durable_source_metadata` (depends on `m157_recovery_fields`)

| Column | Type | Purpose |
|--------|------|---------|
| `source_storage_provider` | VARCHAR(50) | `local` or `supabase` |
| `source_storage_key` | VARCHAR(1000) | Object key in durable storage |
| `source_original_filename` | VARCHAR(500) | Original user-provided filename |
| `source_content_type` | VARCHAR(200) | MIME type |
| `source_size_bytes` | BIGINT | Byte count of original source |
| `source_sha256` | VARCHAR(64) | Hex SHA-256 checksum |
| `source_storage_bucket` | VARCHAR(200) | Bucket name (Supabase) |
| `source_uploaded_at` | TIMESTAMPTZ | When durable upload completed |

All columns are **nullable** for backward compatibility with pre-M15.7.1 jobs.

Index: `ix_ingestion_jobs_source_storage_key` for fast retry lookups.

## Error Semantics

| Scenario | Error Code | Recovery Status |
|----------|-----------|-----------------|
| Local missing + Durable OK + SHA-256 ✓ | (recovered) | NONE → proceeds |
| Local missing + Durable OK + SHA-256 ✗ | SOURCE_FILE_INTEGRITY_MISMATCH | PERMANENT_FAILURE |
| Local missing + No durable record | SOURCE_FILE_MISSING | PERMANENT_FAILURE |
| Local missing + Durable key not in storage | SOURCE_FILE_MISSING | PERMANENT_FAILURE |
| Storage temporarily unavailable | SOURCE_STORAGE_UNAVAILABLE | RETRYABLE |
| Storage permission failure | SOURCE_STORAGE_PERMISSION_ERROR | PERMANENT_FAILURE |

## Security

- **No credentials in PostgreSQL**: Only the storage OBJECT KEY is stored. No signed URLs, tokens, or secrets.
- **Path traversal prevention**: Storage keys are sanitized; resolved paths are verified to stay within storage root.
- **Secret sanitization**: Error messages strip Bearer tokens, passwords, and connection strings.
- **Supabase credentials**: Loaded from environment variables only, never logged.

## API Changes

### IngestionJobResponse (extended)

New fields returned by all ingestion job endpoints:

```json
{
  "source_storage_provider": "local",
  "source_has_durable_backup": true,
  "source_sha256_prefix": "a1b2c3d4e5f6...",
  "source_size_bytes": 1234567,
  "source_uploaded_at": "2026-09-22T21:00:00Z"
}
```

Note: `source_storage_key` is **intentionally excluded** from the API response to avoid leaking internal storage paths.
