# M15.0 UI/Theme Audit

## 1. Current Theme Architecture
- **Framework**: Tailwind CSS v4 alongside standard React/Next.js components.
- **Global Configuration**: Tailwind configuration is inlined within `frontend/src/app/globals.css` using the `@theme inline` directive.
- **Component Library**: shadcn/ui is utilized, with its CSS variable system mapping to Tailwind color variables (e.g., `--background`, `--foreground`, `--primary`, `--card`).
- **Dark Mode Strategy**: Currently implemented via a `.dark` class in `globals.css`. However, an extensive amount of hardcoded Tailwind color utilities (e.g., `bg-slate-900`, `border-slate-800`, `text-slate-300`) are manually applied to components rather than strictly adhering to semantic shadcn tokens.

## 2. Global Color Tokens (`globals.css`)
- **Background/Surface**: `--background` (`#F8FAFC` light, `#0B0E14` dark), `--card` (`#FFFFFF` light, `#111721` dark).
- **Primary/Accent**: `--primary` (`#1E3A8A` light, `#3B82F6` dark), `--ring` (`#1E3A8A` light, `#3B82F6` dark).
- **Semantic/Status**: `--destructive` (`#B91C1C` light, `#EF4444` dark). Chart colors (`--chart-1` through `--chart-5`) cover blue, green, amber, red, and purple/slate.
- **Sidebar**: Specific variables for sidebar elements (`--sidebar`, `--sidebar-border`, `--sidebar-primary`, etc.).

## 3. Hardcoded Color Locations
There are over 500 instances of hardcoded color utility classes across the codebase. Key patterns include:
- `bg-slate-900`, `bg-slate-950`, `bg-slate-800` (for dark mode surfaces and panels)
- `border-slate-800`, `border-slate-700` (for borders and dividers)
- `text-slate-400`, `text-slate-300`, `text-slate-200`, `text-slate-500` (for typography)
- `bg-blue-600/20`, `text-blue-400` (for interactive or active states)
- `bg-red-500/20`, `text-red-500` (for errors, critical anomalies)
- `bg-amber-500/10`, `text-amber-400` (for warnings)
These classes override or ignore the global CSS variables in many components.

## 6. Graph/Map-Specific Styling
- **Graph (`NetworkGraph.tsx`, `GraphNodeDetails.tsx`)**: Graph node and edge colors are likely passed as JavaScript props or configured directly in the canvas/SVG rendering logic, aside from the HTML container classes.
- **Map (`CrimeHotspotsMap.tsx` and MapLibre configurations)**: The base map style URL determines the main map appearance. UI overlays (popups, filters, legends) use hardcoded Tailwind classes (e.g., `bg-slate-900/40`).

## 7. Semantic Status Colors
Currently mapped correctly in both variables and hardcoded classes:
- **Red / Destructive**: Used for critical errors, anomalies, high severity alerts (`text-red-500`, `bg-red-500/20`).
- **Amber / Warning**: Used for cautions or pending items (`text-amber-400`, `bg-amber-500/10`).
- **Green / Success**: Used for healthy status or completed actions (`text-emerald-400`, `bg-emerald-500/10`).
- **Blue / Active**: Used for selections and primary actions (`text-blue-400`, `bg-blue-600/20`).

## 8. Recommended Safe Theme Conversion Strategy
1. **Update `globals.css` Dark Mode Tokens**: Redefine the `.dark` (and optionally `:root`) variables to align with the M15.0 requirements:
   - `--background`: `#050505`
   - `--card` / `--popover`: `#080808` to `#0D0D0D`
   - `--border` / `--input`: `#222222`
   - `--primary`: Restrained green (e.g., `#10B981` or similar)
   - `--foreground`: `#F5F5F5`
   - `--muted-foreground`: `#666666` or `#9A9A9A`
2. **Global Search and Replace of Hardcoded Slate Classes**: Since many components use hardcoded `slate-*` classes, these need to be safely mapped to the new near-black theme. 
   - `bg-slate-900`, `bg-slate-950` -> `bg-[#050505]`, `bg-[#080808]`, or `bg-[#0D0D0D]`
   - `border-slate-800`, `border-slate-700` -> `border-[#222222]` or `border-[#2A2A2A]`
   - `text-slate-400` -> `text-[#9A9A9A]`
   - `text-slate-500`, `text-slate-600` -> `text-[#666666]`
   - `text-slate-200`, `text-slate-300` -> `text-[#F5F5F5]`
3. **Preserve Semantic Colors**: Do NOT alter instances of `red-*`, `amber-*`, `emerald-*`, or `green-*` when performing replacements.
4. **Targeted Replacement for Primary Accents**: Replace hardcoded `blue-*` classes (which acted as the previous primary accent) with restrained green accents, ensuring semantic meaning isn't lost.
5. **Component Auditing**: Systematically apply the replacements to layout files, workspace panels, and graph/map overlays without touching component logic, hooks, or state.

## 9. Files That Should NOT Be Modified
- `backend/**/*` (All FastAPI routes, database models, ML logic, scripts, tests)
- `frontend/src/services/**/*` (API fetch logic)
- `frontend/src/store/**/*` (Zustand state management)
- `frontend/src/hooks/**/*` (Custom React hooks)
- ANY API endpoints or fetching logic inside component files.
- ANY database interactions, queries, algorithms (Louvain/Leiden), or NLP logic.
- `package.json`, `package-lock.json`, `tsconfig.json`
- `docker-compose.yml`, `Dockerfile`
