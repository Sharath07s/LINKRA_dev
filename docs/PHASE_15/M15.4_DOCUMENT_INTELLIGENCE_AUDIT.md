# M15.4 Document Intelligence Audit

## Current State

The current architecture implements the structured intelligence path through `IngestionJob` and `EntityCandidate`, leading to `CanonicalEntity` and `EntityRelationship`. However, the document-level semantic retrieval path is incomplete. While a `DocumentChunk` table and `pgvector` exist, the integration of chunking into the ingestion pipeline, the proper alignment of schema fields for provenance, and the use of semantic evidence in Copilot RAG are missing or not fully integrated.

## Component Audit

1. **Existing Document model**: No standalone `Document` model exists. Documents are conceptually tracked via `IngestionJob` (`backend/app/models/ingestion.py`).
2. **Existing DocumentChunk model**: Present in `backend/app/models/document.py`. Contains `source_id`, `content`, `metadata_json`, `embedding` (Vector 384). It lacks explicit relational fields for `ingestion_job_id`, `page_number`, `source_row`, and `chunk_index` (though these might be implied inside `metadata_json`).
3. **Existing Evidence model**: No standalone `Evidence` model exists. Evidence is currently represented via `evidence_text`, `source_page`, and `source_row` directly on the `EntityRelationship` model (`backend/app/models/relationship.py`).
4. **Existing pgvector/vector-store implementation**: 
   - Migration `6ebe98bc6b0e_add_document_chunks_and_vector_extension.py` adds the `vector` extension and `document_chunks` table.
   - `VectorStore` class exists in `backend/app/ai/rag/vector_search.py` containing `index_document` and `semantic_search` using `pgvector.sqlalchemy`.
5. **Existing embedding provider/configuration**: `HuggingFaceEmbeddings(model_name="all-MiniLM-L6-v2")` is hardcoded in `VectorStore` initialization.
6. **Existing VectorStore.semantic_search()**: Exists in `backend/app/ai/rag/vector_search.py`. Uses cosine distance via pgvector.
7. **Existing RAG tool**: `_tool_rag_evidence_lookup()` is implemented in `backend/app/ai/copilot/orchestrator.py` but is somewhat disconnected from the actual chunking logic and entity query context.
8. **Existing Copilot orchestration**: `CopilotOrchestrator.handle_query()` in `backend/app/ai/copilot/orchestrator.py` integrates tools based on intents.
9. **Existing document ingestion/parsing pipeline**: Present in `backend/app/ingestion/service.py` and `backend/app/ingestion/parsers/`. Contains structured parsing for PDF, TXT, CSV, JSON, and NLP extraction. Chunking into `DocumentChunk` is *not* currently integrated here.
10. **Existing ingestion jobs**: Tracked via `IngestionJob` in `backend/app/models/ingestion.py`.
11. **Existing source/page/row provenance fields**: `EntityCandidate` and `EntityRelationship` have `source_page` and `source_row`. `IngestionJob` tracks `file_name` and `source_type`.
12. **Existing Alembic migrations**: Vector migration `6ebe98bc6b0e` is already in place.
13. **Existing PostgreSQL/pgvector configuration**: Assumed to be functional based on the presence of the migration.
14. **Existing tests**: `backend/app/tests/test_copilot_tooling.py` exists, but comprehensive RAG integration tests with actual chunk insertion are missing.

## Missing Components & Required Updates

- **Schema Update**: `DocumentChunk` needs to be updated (or migrated) to formally support `ingestion_job_id` (foreign key) instead of just `source_id`, plus `page_number`, `source_row`, and `chunk_index` for strong provenance.
- **Pipeline Integration**: `process_ingestion` in `backend/app/ingestion/service.py` must create and persist `DocumentChunk`s with embeddings during document processing.
- **Embedding Configuration**: The embedding configuration should be driven by environment variables (e.g. `EMBEDDING_MODEL_NAME`) rather than hardcoded in `VectorStore`.
- **RAG Tool Refinement**: `_tool_rag_evidence_lookup` needs to return properly formatted chunks with full provenance and the Copilot prompt must be updated to clearly distinguish between `DOCUMENT EVIDENCE` and `STRUCTURED RELATIONSHIP EVIDENCE`.

## Implementation Plan

1. **Database Foundation**: Create an Alembic migration to update `document_chunks` table, replacing `source_id` with `ingestion_job_id` (FK), and adding `page_number`, `source_row`, and `chunk_index`.
2. **Chunking & Embedding Generation**: Update `VectorStore` to accept these new fields. Integrate `VectorStore.index_document` into `backend/app/ingestion/service.py` (`process_ingestion`). Ensure embeddings are generated from actual parsed text.
3. **Semantic Search Service**: Refine `VectorStore.semantic_search` to return the new provenance fields.
4. **Copilot RAG Tool**: Update `_tool_rag_evidence_lookup` to consume the updated semantic search and populate `context_data["evidence"]` with precise provenance.
5. **Source-Grounded Prompting**: Update the `SYSTEM_PROMPT` in `CopilotOrchestrator` to format document evidence properly as instructed.
6. **Testing & Validation**: Run a real ingestion using `test_fir.txt` or a PDF, verify chunk creation, semantic search, and the Copilot response grounding. Add tests to `test_copilot_tooling.py` or a new test file.
