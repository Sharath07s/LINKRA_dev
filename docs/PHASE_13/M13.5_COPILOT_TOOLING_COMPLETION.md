Audit the current LINKRA Copilot implementation and make the existing SQL, Neo4j, and RAG tooling genuinely usable by the Copilot. The tools must be read-only, parameterized, RBAC-aware, and return bounded results, preserving evidence and provenance.

## 3. SQL Capabilities
Bounded tools added/completed:
- `_tool_sql_relationship_lookup`: Uses SQLAlchemy ORM to fetch verified relationships for a canonical entity (LIMIT 20).
- `_tool_entity_explainability_lookup`: Existing tool, utilizes strict backend ORM functions for entity retrieval.
- `_tool_investigation_lookup`: Parameterized UUID query against `Investigation` table.

## 4. Neo4j Capabilities
Bounded tools added/completed:
- `_tool_neo4j_graph_lookup`: Maps to `Neo4jIntelligenceService.get_entity_neighborhood` (Max nodes: 50, depth: 2).
- `_tool_neo4j_anomaly_lookup`: Maps to `Neo4jAnomalyService.get_anomalies_for_entity`.
- `_tool_neo4j_prediction_lookup`: Maps to `Neo4jPotentialLinkService.get_potential_links_for_entity` (Limit: 5).
All Cypher strings are strictly parameterized in `cypher_queries.py`.

## 5. RAG Capabilities
Bounded tools added/completed:
- `_tool_rag_evidence_lookup`: Uses `VectorStore.semantic_search` to query pgvector (Top K: 3). Source documents are embedded into the context explicitly as "RAG_CHUNK" evidence types with similarities, preserving their read-only context.

## 6. Query Planning Changes
`handle_query` now explicitly maps `CopilotIntent` variants to allowed bounded tools.
- **ENTITY_LOOKUP**: SQL explainability, fuzzy search
- **RELATIONSHIP_LOOKUP**: SQL relationship lookup, Neo4j graph lookup
- **GRAPH_EXPLORATION**: Neo4j graph lookup
- **EVIDENCE_LOOKUP**: RAG search
- **ANOMALY_EXPLANATION**: Neo4j anomaly detection
- **POTENTIAL_LINK_EXPLANATION**: Neo4j link predictions

## 7. Security Controls
- Arbitrary SQL execution is impossible (no `engine.execute` with raw text).
- Arbitrary Cypher execution is impossible (no `session.run` with raw text).
- 100% parameterization.
- The `SYSTEM_PROMPT` enforces strict data boundaries: structural anomalies are not guilt, potential links are not confirmed.
- Empty entity searches return `INSUFFICIENT_DATA` safely rather than LLM hallucination.

## 8. RBAC Behavior
- All endpoints remain under FastAPI `Depends(get_current_user)`.
- The `current_user` dict propagates fully into `CopilotOrchestrator.handle_query` and the bounded tools.
- *Limitation*: The current schema lacks fine-grained row-level ownership models for investigations and entities. RBAC relies on global application authentication.
