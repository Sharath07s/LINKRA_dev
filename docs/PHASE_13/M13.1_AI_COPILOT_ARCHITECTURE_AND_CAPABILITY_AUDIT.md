# M13.1 — AI Investigator Copilot Architecture & Capability Audit

## 1. Audit Objective
The objective of this audit is to establish the true engineering state of the AI Investigator Copilot prior to implementation. It evaluates intent routing, grounding architecture, hallucination constraints, API traces, and readiness for real-data validation.

## 2. Official Phase 13 Scope
Based on the `docs/SIH26189_PHASE_MAP.md` document, Phase 13 is officially defined as:
**Phase 13: AI Copilot**
- **Objective:** Implement a conversational assistant for graph and document queries.
- **Key Deliverables:** Intent detection engine, Tool execution framework (SQL, Cypher, RAG).

*Note on conflict:* `docs/IMPLEMENTATION_ROADMAP.md` refers to Phase 13 as "Reporting Engine". The audit proceeds using the authoritative Phase Map definition of Phase 13 as AI Copilot.

## 3. Existing Copilot Architecture
The system contains two disconnected Copilot paradigms:
1. **Legacy Architecture:** An older keyword-based fallback system in `app/api/v1/chat.py` utilizing `IntentEngine` and `QueryPlanner`.
2. **M13 Architecture:** A new orchestration framework in `app/ai/copilot/orchestrator.py` bound to `/api/v1/copilot/chat`.

## 4. Backend Components
- `app/api/v1/copilot.py`: Exposes the POST `/api/v1/copilot/chat` endpoint.
- `app/ai/copilot/orchestrator.py`: Orchestrates context fetching (entities, anomalies, evidence) and formulates strictly constrained LLM prompts with deterministic fallback.
- `app/ai/copilot/intent_router.py`: Determines intent using keyword mapping with LLM fallback.

## 5. Frontend Components
- `frontend/src/app/copilot/page.tsx`: The primary Copilot interface.
- `frontend/src/services/chat.service.ts`: The service responsible for sending messages.
- **Finding:** The frontend is actively calling the legacy `/chat/` endpoint instead of the newly defined `/api/v1/copilot/chat`. The integration is incomplete.

## 6. Copilot API / Execution Flow
**Trace:**
1. Frontend calls `chatService.sendMessage(query)`
2. Request goes to `POST /api/v1/chat/` (Legacy) -> Expected: `POST /api/v1/copilot/chat` (M13)
3. Orchestrator extracts intent via `IntentRouter`.
4. Orchestrator fetches explainability context via `get_entity_explainability` if `entity_id` is present, or performs a fuzzy search.
5. `FallbackManager` executes the LLM prompt.
6. Returns bounded answer or deterministic structured context on failure.

## 7. Intent Routing Audit
- Defined in `IntentRouter`.
- Extracted intents: ANOMALY_EXPLANATION, POTENTIAL_LINK_EXPLANATION, RELATIONSHIP_LOOKUP, EVIDENCE_LOOKUP, INVESTIGATION_SUMMARY, COMPARISON, GRAPH_EXPLORATION, ENTITY_LOOKUP, GENERAL_INTELLIGENCE_QUERY.
- **Status:** IMPLEMENTED.

## 8. Grounding Audit
- The orchestrator fetches context data (entities, evidence, analytics, anomalies, potential links) via existing `get_entity_explainability` logic.
- However, full generalized SQL/Cypher tool execution framework is missing if no explicit entity/investigation is provided.
- **Status:** PARTIALLY IMPLEMENTED.

## 9. Explainability Audit
- Real explainability APIs are used to feed context to the Copilot.
- **Status:** IMPLEMENTED.

## 10. LLM / Fallback Provider Audit
- LLM requests route through `FallbackManager`.
- If LLMs fail, a `_deterministic_fallback` gracefully returns structured Markdown displaying evidence, anomalies, and potential links without hallucination.
- **Status:** IMPLEMENTED.

## 11. Citation & Provenance Audit
- The orchestrator includes source evidence in its payload and instructs the LLM to cite them. However, no structured click-through citation rendering exists yet on the frontend.
- **Status:** PARTIALLY IMPLEMENTED.

## 12. Hallucination Controls Audit
- The `SYSTEM_PROMPT` enforces strict rules (e.g., "DO NOT invent fake entities").
- Deterministic fallback prevents any generation if confidence is lost.
- **Status:** IMPLEMENTED.

## 13. Confirmed / Inferred / Predicted Audit
- The prompt explicitly instructs: "NEVER describe a potential link as a confirmed relationship. NEVER describe a structural anomaly as evidence of criminal guilt."
- Deterministic fallback labels them "Potential Links (Based strictly on graph topology)".
- **Status:** IMPLEMENTED.

## 14. Graph Grounding Audit
- The orchestrator utilizes Neo4j through `get_entity_explainability`.
- **Status:** IMPLEMENTED.

## 15. Evidence Grounding Audit
- Evidence objects tied to relationships and entities are injected into the context.
- **Status:** IMPLEMENTED.

## 16. Anomaly Explanation Audit
- Structural anomalies are successfully extracted and passed to the LLM for explanation.
- **Status:** IMPLEMENTED.

## 17. Predicted-Link Explanation Audit
- Jaccard/Preferential attachment explanations from Phase 10 are preserved and passed to the LLM.
- **Status:** IMPLEMENTED.

## 18. Empty-Data Behavior
- The orchestrator correctly returns an `INSUFFICIENT_DATA` state if no context matches the query.
- **Status:** IMPLEMENTED.

## 19. Prompt Injection / Security Audit
- Existing tests prove Cypher injection mitigation in relationship extraction, but no direct prompt injection testing exists for the Copilot conversational endpoints to prevent jailbreaking.
- **Status:** MISSING.

## 20. RBAC Audit

- However, internal calls like `get_entity_explainability(query.entity_id, db=db, current_user=None)` do not properly propagate user permissions for fine-grained access control.
- **Status:** PARTIALLY IMPLEMENTED.

## 21. Mock / Fabricated Intelligence Audit

## 25. Findings

### CRITICAL
- The frontend `chat.service.ts` is incorrectly hooked up to the legacy `/chat/` endpoint instead of the new `/copilot/chat` M13.1 orchestrator.

### HIGH
- Lack of prompt injection testing for Copilot input messages.
- RBAC validation does not propagate to the `get_entity_explainability` data fetching layer.

### MEDIUM
- Structured citations are not fully preserved in a deterministic click-through UI format.
- Context retrieval relies primarily on direct entity matching rather than a robust SQL/Cypher translation framework.

### LOW
- Phase roadmap documentation conflict between Phase Map (AI Copilot) and Implementation Roadmap (Reporting).
