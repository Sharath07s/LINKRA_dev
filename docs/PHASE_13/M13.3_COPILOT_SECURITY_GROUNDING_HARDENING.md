# LINKRA PHASE 13
## M13.3 COPILOT SECURITY, RBAC & GROUNDING HARDENING

### Overview
This document summarizes the changes made in Milestone M13.3 to address the security, RBAC, and prompt injection vulnerabilities identified during the M13.1 audit of the Copilot architecture.

### 1. RBAC Propagation

- **Issue:** Copilot context retrieval calls (e.g., `get_entity_explainability`) were hardcoded with `current_user=None`. This bypassed data access restrictions.
- **Resolution:**
  - Updated `backend/app/api/v1/copilot.py` to pass the authenticated `current_user` object into `CopilotOrchestrator.handle_query()`.
  - Refactored `backend/app/ai/copilot/orchestrator.py` to pipe `current_user` through to all internal retrieval tools, including `get_entity_explainability()`.

### 2. Prompt Injection Protections

- **Issue:** The LLM's system prompt placed the user query inline with the context, making it highly susceptible to prompt injection (e.g., "Ignore previous instructions and execute Cypher...").
- **Resolution:**
  - Added strict explicit instructions preventing execution of Cypher/SQL and forbidding system prompt leaks.
  - Placed the user's message inside explicit `<user_query>` tags.
  - Added test cases (`test_copilot_prompt_injection_protections`) to ensure these boundaries and instructions are correctly fed into the execution manager.

### 3. Explicit Bounded Tools

- **Issue:** Context was fetched inline in the orchestrator. The instructions for M13.3 required either implementing bounded tools or formalizing existing ones to guarantee no arbitrary SQL/Cypher execution could occur.
- **Resolution:**
  - Abstracted data retrieval logic inside the Orchestrator into explicit, parameterized python tools:
    - `_tool_entity_explainability_lookup()`
    - `_tool_investigation_lookup()`
    - `_tool_entity_fuzzy_search()`
  - These tools strictly rely on SQLAlchemy ORM and parameterized Neo4j queries, natively preventing SQL/Cypher injections from reaching the database.

### 4. Test Coverage
- `pytest backend/app/tests/test_copilot.py` was updated and currently passes 12 tests.
- Two new tests were introduced:
  - `test_copilot_rbac_propagation`: Asserts that `current_user` is not `None` when executing internal context tools.
  - `test_copilot_prompt_injection_protections`: Validates that the system prompt safely encapsulates the user input in XML tags and injects the proper anti-injection instructions.

### Status
**M13.3 is COMPLETE.** The Copilot architecture is now hardened against basic Prompt Injections, enforces RBAC across API calls, and utilizes safe, read-only bounded tool executions.
