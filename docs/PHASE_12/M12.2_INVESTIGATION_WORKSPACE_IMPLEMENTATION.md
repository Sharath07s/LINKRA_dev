# Phase 12: Investigation Workspace Replacement

**Milestone:** M12.2
**Status:** COMPLETE
**Date:** September 2026

## Objective
The objective of this phase was to replace the mocked investigation workspace with a real, fully integrated LINKRA investigation workspace. The frontend previously relied on a `MOCK_CASE` paradigm, utilizing hardcoded intelligence and dummy components, while the backend contained mocked endpoints to support this UI.

## Implementation Details

### Backend API Un-mocking
- **`investigations.py`**: 
  - Added a new `GET /{id}` endpoint to fetch genuine `Investigation` records and their joined `Crime` details.
  - Upgraded `GET /{id}/timeline` to fetch real `CrimeStatusHistory` events.
  - Upgraded `GET /{id}/locations` to fetch the real crime's geographical coordinates.
  - Upgraded `GET /{id}/threat-assessment` and `GET /{id}/health` to return valid (but zeroed/empty) defaults when intelligence is sparse, avoiding hallucination.
- **`crimes.py`**:
  - Removed all hardcoded mock responses from `GET /{id}/summary`, `GET /{id}/entities`, and `GET /{id}/timeline`.
  - Re-wired these endpoints to query the PostgreSQL source of truth and return real `CanonicalEntity` relationships, `Evidence`, and `CrimeStatusHistory` records.

### Frontend Integration
- **`investigation-board/page.tsx`**: 
  - Eliminated the mocked `currentCase` object.
  - Integrated with `investigationService.getInvestigation()` to load the specific investigation context based on URL parameters or the active list.
  - Re-wired the graph logic to fetch `/api/v1/investigations/{id}/entities` and specifically query the Neo4j subgraph for actual case entities instead of universally fetching high-risk networks.
  - Added native empty states and loading boundaries.
- **`EvidenceIntel.tsx`**: Removed fabricated digital and physical evidence arrays. The component now utilizes the `investigationId` prop to display real evidence or gracefully defaults to an "Empty Evidence" state.
- **`AICopilot.tsx`**: Removed hardcoded reasoning traces ("Night Owl", "Ramesh Kumar"). Converted to an empty "Copilot Ready" state awaiting integration with the unified `/api/v1/copilot/chat` endpoint.
- **`CaseMapPanel.tsx`**: Added an empty state to elegantly handle investigations lacking verified geographical coordinates without rendering an empty grid indefinitely.

## Anti-Fabrication Rule Validation
Because the LINKRA platform strictly prohibits fabricating intelligence, the Investigation Workspace correctly reflects the current sparse state of the test database. 

When viewing a newly created or sparse investigation, the UI authentically displays:
- "No detailed summary or modus operandi is available"
- "No Entities Identified"
- "No Priority Alerts"
- "No Evidence"
- "No Verified Locations"
