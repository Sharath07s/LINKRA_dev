# Milestone 1.7: Knowledge Graph (Idempotent Synchronization)

## Overview
This milestone establishes the foundational graph architecture for LINKRA by formalizing the projection of structured intelligence data (`CanonicalEntity`, `EntityRelationship`) from the authoritative PostgreSQL database into the Neo4j Aura graph database.

## Architecture

**PostgreSQL is the single source of truth.** The Neo4j graph acts as an indexing and traversal projection, answering complex multi-hop neighborhood queries that are computationally expensive in a relational store.

### Canonical Mapping
- **Postgres Entity:** `CanonicalEntity.id` (UUID) -> **Neo4j Node:** `(:Entity {id: <uuid>})`
- **Postgres Relationship:** `EntityRelationship.id` (UUID) -> **Neo4j Edge:** `()-[r:TYPE {id: <uuid>}]->()`

By embedding the PostgreSQL UUID explicitly inside the Neo4j nodes and edges, we achieve **Idempotent Synchronization**. Operations can be run repeatedly without duplicating nodes or relationships.

## Implementation Details

### Label Strategy
All projected nodes receive the `Entity` base label. This allows global bounded traversal via Cypher (e.g., `MATCH (e:Entity)`). Nodes also receive secondary descriptive labels based on their type (e.g., `(:Entity:Person)`, `(:Entity:Vehicle)`).

### Constraints
A Neo4j uniqueness constraint guarantees data integrity:
```cypher
CREATE CONSTRAINT IF NOT EXISTS FOR (e:Entity) REQUIRE e.id IS UNIQUE
```

### New APIs
The backend now exposes a dedicated `graph` router.
- `GET /api/v1/graph/entity/{entity_id}`: Retrieves a single node and its properties formatted for React Flow graph rendering.
- `GET /api/v1/graph/subgraph/{entity_id}`: Retrieves the N-degree neighborhood. Features query bounded limits (`depth`, `max_nodes`) to ensure stability.

### Rebuild Script
If the Neo4j Aura instance is wiped, it can be entirely reconstructed using the `backend/scripts/rebuild_graph.py` utility.
