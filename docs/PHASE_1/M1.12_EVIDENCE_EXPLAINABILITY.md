# M1.12 Evidence & Explainability

## Overview
The **M1.12 Evidence & Explainability** milestone adds robust provenance and traceability to the LINKRA criminal intelligence platform. Its primary goal is to ensure every node, edge, structural anomaly, and potential link discovered by the AI system can be deterministically traced back to its underlying source data (e.g. CCTNS FIRs, CDR logs).

This layer is critical for turning "black box" graph AI insights into legally and operationally defensible intelligence.

## Key Capabilities

1. **Source Provenance via Ingestion Jobs**: Every canonical entity and relationship generated by the ingestion pipeline natively retains its `ingestion_job_id`. The new Explainability API maps this ID back to the exact file, document, page, and line number from which the entity was extracted.
2. **Aggregated Intelligence Views**: A new `/api/v1/explainability/entity/{entity_id}` endpoint consolidates:
   - Direct evidence (source files, CDR logs).
   - Observed relationships (factual linkages with weights).
   - Structural analytics (Degree centrality, Component distribution).
   - Anomaly signals (AI-driven graph anomaly detection with detailed reasoning).
   - Potential links (AI-driven missing link prediction).
3. **Structured Explanations**: Analytics modules in Neo4j (`anomaly.py` and `predictions.py`) now return a deterministic JSON explanation payload containing `reason`, `method`, `metrics`/`weights`, and `interpretation`.
4. **Investigation Workspace Integration**: The Intelligence Workspace UI (Node Inspector) was significantly overhauled to consume the unified Explainability endpoint. It now features dedicated sections for **Source Evidence** (including document provenance) and displays structured explanations for all AI-generated signals.

## Architecture

### Backend Changes
- **Schemas**: `AnomalyExplanation`, `PotentialLinkExplanation`, and `ExplainabilityResponse` added to `backend/app/schemas/graph.py` to standardize JSON outputs.
- **Explainability API**: A new router in `backend/app/api/v1/explainability.py` aggregates data from PostgreSQL (the single source of truth for evidence and entities) and Neo4j (the projection layer for analytics).
- **AI Engine Updates**: 
  - `anomaly.py` and `predictions.py` refactored to emit structured explanation objects instead of raw string messages.

### Frontend Changes
- **Unified Querying**: `GraphNodeDetails.tsx` was optimized to make a single call to `/explainability/entity/{id}` instead of 4 separate parallel analytics endpoints.
- **Evidence Panel**: A new UI component inside the Node Inspector renders direct source provenance (e.g., File Name, Page, Row).
- **Clear AI Warnings**: AI-driven suggestions (Anomalies and Potential Links) are explicitly labeled with disclaimers emphasizing that they are based on structural graph topology, not confirmed criminal activity.

## Testing & Verification
- Comprehensive tests added in `backend/app/tests/test_explainability.py` and existing tests in `test_graph_predictions.py` updated.
- The `uuid` issue with SQLAlchemy/SQLite in the test suite was resolved by explicitly casting string inputs to UUID before executing ORM queries.
- The full test suite passes locally, verifying zero regressions across M1.1 - M1.11 features.
