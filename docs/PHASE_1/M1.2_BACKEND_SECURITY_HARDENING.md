# M1.2 — Backend Security Hardening

**Status:** ✅ COMPLETE  
**Date:** 2026-08-27  
**Branch/Scope:** Additive security fixes — no schema changes, no DB changes, no feature removals

---

## Objective

Harden the existing ICA_AI FastAPI backend against the most critical OWASP vulnerabilities while preserving all existing functionality.

---

## Changes Applied

### 1. RBAC Enforcement (Role-Based Access Control)

**Files:** `executive.py`, `officer.py`, `system_health.py`

- Replaced `get_current_active_user` with `RoleChecker([...])` on **all** endpoints.
- Role assignments:
  - `/api/v1/executive/*` → `["EXECUTIVE", "ADMIN"]`
  - `/api/v1/officer/*` → `["OFFICER", "ADMIN"]`
  - `/api/v1/system/health/*` → `["ADMIN"]` (most privileged — system internals)
- The existing `RoleChecker` class in `deps.py` was already implemented; it was simply not applied.

### 2. CORS & Security Headers (main.py)

**File:** `main.py`

- **CORS methods** restricted from `["*"]` to explicit allowlist: `GET, POST, PUT, DELETE, OPTIONS, PATCH`
- **CORS headers** restricted from `["*"]` to: `Content-Type, Authorization, Accept`
- **Security headers middleware** injected on all responses:
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `X-XSS-Protection: 1; mode=block`
  - `Referrer-Policy: strict-origin-when-cross-origin`

### 3. Login Rate Limiting (auth.py)

**File:** `auth.py`

- Added simple in-memory IP-based rate limiter to `/auth/login`.
- Limit: **5 attempts per IP per 60 seconds**.
- Returns HTTP `429 Too Many Requests` on breach.
- Note: This is a lightweight in-process implementation suitable for single-instance deployments. For multi-instance deployments, migrate to a Redis-backed rate limiter (e.g., `slowapi`).

### 4. Cypher Injection Mitigation (Neo4j Parameterization)

**Files:** `neo4j.py`, `officer.py`, `executive.py`, `planner.py`, `recidivism.py`, `recidivism_validator.py`, `intelligence.py`

All f-string Cypher interpolations replaced with Neo4j parameterized queries:

| Before (UNSAFE) | After (SAFE) |
|---|---|
| `f"MATCH (s:Suspect {{id: '{suspect_id}'}})..."` | `"MATCH (s:Suspect {id: $suspect_id})..."` + `parameters={"suspect_id": suspect_id}` |

- `execute_query()` in `Neo4jIntelligenceService` now accepts an optional `parameters: Dict[str, Any]` argument.
- `cypher_queries.py` already used parameterized queries (`$param_name` syntax) and required no changes.

### 5. Error Handling Sanitization

**Files:** `executive.py`, `officer.py`, `system_health.py`, `predictive.py`

- Replaced `raise HTTPException(detail=str(e))` and `return {"error": str(e)}` patterns.
- All broad `except Exception as e:` blocks now:
  1. Log the full error via `logger.error(...)` (server-side only)
  2. Return a **generic, non-leaking** error message to the client
- Added `logging.getLogger(__name__)` to all affected files.

### 6. Input Validation (Pydantic Schemas)

**Files:** `schemas/chat.py`, `schemas/user.py`

- `ChatQuery.query`: Added `min_length=1`, `max_length=2000`, `strip_whitespace=True`
- `UserBase.badge_number`: Added `min_length=3`, `max_length=20`, alphanumeric pattern constraint
- `UserCreate.password` / `UserUpdate.password`: Added `min_length=8`, `max_length=128`
- `UserBase.first_name`, `last_name`: `max_length=100`
- `UserBase.phone`: `max_length=15`
