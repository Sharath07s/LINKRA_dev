# M1.6 Evidence-Based Relationship Extraction

## Overview
Milestone 1.6 introduces the Relationship Extraction layer to the LINKRA Intelligence Pipeline. This layer is responsible for discovering, extracting, and persisting relationships (edges) between resolved Canonical Entities, forming the foundation of the Knowledge Graph (M1.7).

Following LINKRA's core principle of **"Evidence > Guessing"**, relationships are only extracted when explicitly supported by the source document (either structurally or through NLP triggers), preventing "hallucinated" connections.

## Architecture

1. **Entity Extractor**: Extracts raw `EntityCandidates`.
2. **Entity Resolver**: Resolves candidates to `CanonicalEntities`.
3. **Relationship Extractor (M1.6)**: Analyzes the original document context of the *resolved candidates* to deduce relationships.

### The Domain Model
Relationships are stored in PostgreSQL using the `EntityRelationship` model:
- `source_entity_id`: UUID (FK to CanonicalEntity)
- `target_entity_id`: UUID (FK to CanonicalEntity)
- `relationship_type`: String (e.g., `COMMUNICATED_WITH`, `ASSOCIATED_WITH`, `REGISTERED_TO`)
- `confidence`: Float (0.0 to 1.0)
- `extraction_method`: String (e.g., `STRUCTURED_CDR`, `NLP_TRIGGER`)
- `event_timestamp`: DateTime (optional)
- `ingestion_job_id`: UUID (Provenance to original document)
- `source_page` / `source_row`: Integer (Exact location in document)

Relationships are synchronized in real-time to Neo4j.

## Extraction Methodologies

### 1. Structured Extraction (High Confidence)
Applies to structured data formats (e.g., CSV, JSON) such as Call Detail Records (CDRs) or financial logs.
- **COMMUNICATED_WITH**: Extracted when a row contains a `caller` and `callee`. Confidence: 1.0. Preserves `timestamp`.
- **REGISTERED_TO**: Extracted when a row links a `person` (owner) to a `vehicle_number`. Confidence: 1.0.
- **ASSOCIATED_WITH**: Fallback for co-occurring entities in a structured row without a specific schema mapping. Confidence: 0.9.

### 2. Unstructured Extraction (NLP Trigger-Based)
Applies to unstructured text (e.g., FIRs, Police Reports, Interrogation Notes).
Simple entity co-occurrence within a document or sentence is **ignored** to prevent false positives. A relationship is only extracted if an explicit "trigger" phrase bridges the entities in the same sentence.
- **COMMUNICATED_WITH**: Triggered by "called", "spoke to", "contacted". Confidence: 0.8.
- **MET_WITH**: Triggered by "met", "visited". Confidence: 0.8.
- **ASSOCIATED_WITH**: Triggered by "associated with", "accomplice of", "brother of". Confidence: 0.85.

## Persistence and Idempotency
- **PostgreSQL**: A composite unique constraint (`source_entity_id`, `target_entity_id`, `relationship_type`, `ingestion_job_id`, `source_page`, `source_row`, `event_timestamp`) ensures that re-ingesting the exact same document does not duplicate edges, while allowing the same two entities to have multiple distinct relationships (e.g., calling each other at different times).
- **Neo4j**: Synchronized using Cypher `MERGE (a)-[r:TYPE]->(b) SET r += $props`, updating the edge properties without creating duplicates.

## Next Steps
With relationships now being successfully extracted and persisted, M1.7 (Knowledge Graph) will consume this edge data to provide visual graph analysis and multi-hop querying capabilities.
