# Milestone 1.3: RBAC & Authorization Audit

## Overview
A comprehensive authorization audit was conducted across the backend API (v1). It was identified that several critical endpoints lacked appropriate Role-Based Access Control (RBAC) checks, exposing sensitive data and functionality to unauthorized users (and in some cases, to unauthenticated public access).

## Discoveries & Remediation

### 1. Public Exposure of Critical Routes
- **Infrastructure Metrics & Backups** (`infrastructure.py`): Missing auth. Added `ADMIN` RoleChecker.
- **Intelligence Fusion** (`intelligence_fusion.py`): Signals, correlations, priorities, and LLM briefing triggers were fully public. Secured with `EXECUTIVE` and `ADMIN` RoleCheckers.
- **Neo4j Access** (`neo4j.py`): Graph intelligence lookups and the arbitrary Cypher query endpoints were public. Secured lookups with `OFFICER`, `EXECUTIVE`, `ADMIN` and restricted `/query` strictly to `ADMIN`.

### 2. WebSocket Security
- **Command Wall, Alerts, Officer Workspace, Predictive** (`realtime.py`): WebSockets were exposed without authentication. Implemented token-based authentication via query parameter (`?token=...`) using a new `get_ws_user` dependency in `deps.py`.
- **System Health WebSocket** (`realtime.py`): Added `ADMIN` RoleChecker explicitly on top of WS token auth.
- **Notifications WebSocket** (`ws.py`): Added token auth.

### 3. Insufficient Role Restrictions
- **Suspects Management** (`suspects.py`): POST/PUT operations were accessible to any authenticated user. Upgraded to `OFFICER` and `ADMIN`.
- **Command Wall Intelligence Feed** (`command_wall.py`): LLM triggering endpoint was accessible to all. Upgraded to `EXECUTIVE` and `ADMIN`.
- **Predictive Modules** (`predictive.py`, `predictive_explainability.py`, `intents.py`): Added `OFFICER`, `EXECUTIVE`, `ADMIN`.
- **Predictive Validation & Model Monitoring** (`predictive_validation.py`, `model_monitoring.py`): Internal AI metrics were open to all. Restricted strictly to `ADMIN`.

### 4. Broken Auth Gates
- **User Management** (`users.py`): Legacy role strings (`"SCRB Admin"`, `"Admin"`) were used for role checking, which didn't match the DB schema role `ADMIN`. This caused legitimate admins to be denied access or, worse, resulted in silent bypass if misconfigured. Normalized all checks to `ADMIN`.

## Verification
- Added automated tests in `backend/tests/test_auth_rbac.py` to assert that correct roles return `200 OK`, incorrect roles return `403 Forbidden`, and missing auth returns `401 Unauthorized`.
- Syntax checks run successfully.

## Conclusion
The system's API boundary is now properly secured with explicit role-based access controls on all endpoints, ensuring that users can only access endpoints appropriate for their organizational role (`OFFICER`, `EXECUTIVE`, `ADMIN`).
