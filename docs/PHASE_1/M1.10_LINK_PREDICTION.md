# LINKRA — M1.10 Link Prediction / Potential Links

## 1. Objective
Implement Milestone M1.10: Link Prediction. This milestone focuses on predicting *structurally plausible* but currently unobserved relationships between Canonical Entities using the Neo4j Knowledge Graph. The engine relies solely on mathematical graph topology and avoids predicting criminality or assuming guilt.

## 2. Architecture
- **Backend Service**: `Neo4jPotentialLinkService` in `backend/app/ai/neo4j/predictions.py`.
- **API Endpoints**: REST router mapped to `/api/v1/graph/potential-links`.
- **Frontend Component**: Integrated into the node details side panel in `frontend/src/components/GraphNodeDetails.tsx`.
- **Database Engine**: Neo4j Aura Free (using only native bounded Cypher queries).
- **Source of Truth**: PostgreSQL remains the authoritative source. Suggested links are NEVER written to PostgreSQL.

## 3. Structural Signals & Mathematics
The candidate generation engine uses native Cypher to calculate three structural signals simultaneously:

1. **Common Neighbors (Weight 40%)**: Counts nodes $X$ where $A \rightarrow X$ and $B \rightarrow X$. Normalized out of 10.
2. **Jaccard Similarity (Weight 40%)**: Calculates neighborhood intersection over union: $|N(A) \cap N(B)| / |N(A) \cup N(B)|$.
3. **Preferential Attachment (Weight 20%)**: Calculates degree product $degree(A) * degree(B)$. Normalized locally across the candidate set.

> [!NOTE]
> **Adamic-Adar Deferral**
> Adamic-Adar was deferred because querying the independent degrees of every common neighbor creates an O(N*M) Cartesian explosion inside Cypher, violating the Aura Free performance constraints.

## 4. Candidate Generation
To prevent querying the Cartesian product of the entire graph, candidates are bounded locally for a specific focal entity:
`MATCH (a:Entity {id: $entity_id})-[]-(common:Entity)-[]-(b:Entity) WHERE a <> b AND NOT (a)-[]-(b)`

## 5. API Endpoints
- `GET /api/v1/graph/potential-links/{entity_id}?limit=20&min_score=0.4`
- Global endpoint `/top` was deferred because full-graph disjoint-path structural scanning causes Neo4j Aura Free memory limit exhaustion.

## 6. Empty-State Behavior
- The engine calculates the focal entity's degree first. If `degree < 2`, it instantly returns `insufficient_data` and aborts the query to save DB cycles (you cannot have $\ge 2$ common neighbors if you have less than 2 edges).
- The UI gracefully downgrades, showing "No strong structural link candidates found."

## 7. Performance Constraints
- Cypher limits are strictly enforced via the `$limit` parameter, which is capped at a hard maximum of 50 inside the backend layer, regardless of user input.

## 9. Security & Ethics
- All endpoints are protected by `Depends(deps.get_current_active_user)`.
- The frontend strictly labels suggestions as "Suggested Links (M1.10) - Based strictly on shared graph topology. Not confirmed criminal activity." to avoid automated assumption of guilt.
- Predictions are ephemeral analytical reads and are never written to the PostgreSQL source of truth.

## 10. Future Improvements
- Upgrade to Neo4j GDS once the project outgrows the Aura Free tier to enable `Node2Vec` embedding-based link prediction, which can find 3-hop and 4-hop associations efficiently using cosine similarity.
