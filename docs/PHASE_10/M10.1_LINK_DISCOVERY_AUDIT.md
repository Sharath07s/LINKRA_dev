# M10.1 — Link Prediction & Discovery Audit

This document formally audits the existing graph link discovery capabilities of the LINKRA platform, evaluating current algorithms, data suitability, and future ML roadmap items in strict adherence to the anti-fabrication principles.

## 1. Current Graph Data Reality
An audit of the production databases reveals a highly sparse graph environment:
- **PostgreSQL Entities:** 50 `canonical_entities`
- **PostgreSQL Relationships:** 16 `entity_relationships`
- **Neo4j Nodes:** 54 nodes
- **Neo4j Edges:** 16 edges
- **Distribution:** `ASSOCIATED_WITH` (8), `CONNECTED_TO` (4), `USES` (4)
- **Graph Density:** Extremely sparse. The maximum degree is low, and connected components are small.

## 2. Existing Link Discovery Audit (Phase 10 Core)
The platform currently leverages a bounded, pure-Cypher topology analysis implemented in `backend/app/ai/neo4j/predictions.py`.

### Algorithms Evaluated
1. **Common Neighbors (CN):** 
   - **Logic:** `count(DISTINCT common) as cn`
   - **Status:** Correctly implemented. The query forces a lower bound of `cn >= 2` to prevent candidate explosion.
2. **Jaccard Similarity:**
   - **Logic:** `(cn * 1.0) / (degree_a + degree_b - cn)`
   - **Status:** Correctly implemented. Serves as a normalized penalty for high-degree nodes sharing few neighbors.
3. **Preferential Attachment (PA):**
   - **Logic:** `degree_a * degree_b`
   - **Status:** Correctly implemented. Normalized locally within the result set.

**Outcome:** The existing scoring function uses a `(0.40 * CN) + (0.40 * Jaccard) + (0.20 * PA)` composite. It operates strictly on genuine Neo4j graph data without synthetic generation.

## 3. Predicted vs Confirmed Integrity
**Status: SECURE & CORRECT**
- **Persistence:** Potential links are calculated 100% dynamically on-the-fly via the API (`/api/v1/graph_predictions`). They are **never** persisted to PostgreSQL or written back to Neo4j as edges.
- **API Defense:** A predicted link cannot accidentally mutate into a confirmed `EntityRelationship` without explicitly passing through the Phase 1 ingestion/validation pipeline.
- **Frontend Distinction:** The `GraphNodeDetails.tsx` component distinctly isolates these links into a "Suggested Links (M1.10)" panel with the explicit warning: *"Based strictly on shared graph topology. Not confirmed criminal activity."*

## 4. Prediction Explainability
**Status: READY**
The current architecture natively generates a `PotentialLinkExplanation` payload. For example: *"The candidate shares 3 common neighbors with the focal entity and has overlapping local topology (43%)."* This ensures predictions are transparent graph-based suggestions rather than hallucinatory assertions.

## 5. Future Algorithm Feasibility Audit

### Adamic-Adar
- **Infrastructure:** Feasible via pure Cypher using `1 / log(degree)`.
- **Data Suitability:** The graph is currently too sparse (16 edges). The algorithmic penalty applied to high-degree common neighbors would add zero meaningful variance over standard Jaccard.
- **Decision:** **NOT JUSTIFIED**

### Resource Allocation
- **Infrastructure:** Feasible via pure Cypher.
- **Data Suitability:** Same limitation as Adamic-Adar.
- **Decision:** **NOT JUSTIFIED**

### Multi-hop Candidate Discovery
- **Infrastructure:** Feasible in Cypher (`MATCH (a)-[*2..3]-(c)`).
- **Data Suitability:** At current sparsity, multi-hop will return almost nothing. If density increases, unbounded multi-hop causes candidate explosion. 
- **Decision:** **JUSTIFIED LATER** (Requires a strictly bounded graph depth when data volume increases).

### Node Embeddings
- **Infrastructure:** Difficult without Neo4j GDS (which is blocked on Aura Free).
- **Data Suitability:** 54 nodes and 16 edges lack the topological richness required to train meaningful low-dimensional vectors.
- **Decision:** **NOT JUSTIFIED**

### Node2Vec
- **Infrastructure:** Blocked. Requires GDS or heavy external dependencies (NetworkX) which violate scalability rules.
- **Data Suitability:** Sparse graph cannot support meaningful random walks.
- **Decision:** **NOT JUSTIFIED**

### GNN (Graph Neural Networks)
- **Infrastructure:** Blocked. No training infrastructure exists.
- **Data Suitability:** No labeled edge-prediction datasets. Extremely small graph size. Classical heuristics are demonstrably sufficient.
- **Decision:** **NOT JUSTIFIED**

## 7. Implementation Decision & Next Milestone
**Decision:** **DEFER** all advanced ML link discovery models (Embeddings, Node2Vec, GNN, Adamic-Adar). 

**Conclusion:** The existing Link Prediction engine (CN + Jaccard + PA) is algorithmically sound, explainable, computationally efficient, and perfectly suited for the current sparse graph reality. Adding ML dependencies would violate the anti-fabrication and performance principles of the platform for zero intelligence gain.

**Next Milestone:** Do not implement Phase 10 algorithmic enhancements. Wait for data density to increase or proceed to the next actionable roadmap phase (e.g., Phase 11 / Advanced Reporting).
