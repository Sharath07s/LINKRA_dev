# M14.6 Community Visualization

## 1. Objective
Implement Community Visualization to visually represent genuine graph communities derived from the LINKRA Knowledge Graph, distinct from geographic density/hotspots. The primary goal is to use structural algorithms (like Louvain or Leiden) to find associated criminal entities.

## 2. Existing Architecture
The established architecture is preserved:
`PostgreSQL -> FastAPI -> Neo4j Knowledge Graph -> Graph Intelligence -> Next.js / React / MapLibre -> Investigator`

## 3. Infrastructure Audit
Before implementation, an audit of the current Neo4j deployment was conducted:
- **Neo4j Version**: 5.27-aura
- **Neo4j Deployment Type**: Aura Free/Standard
- **GDS Availability**: GDS procedures are installed.
- **Current Graph Size**: 73 nodes, 16 relationships (`ASSOCIATED_WITH`, `CONNECTED_TO`, `USES`).

## 4. Neo4j/GDS Capability
While procedures like `gds.louvain.stream` exist, **graph projections cannot be created**. When executing `CALL gds.graph.project(...)`, the server returns:
> `java.lang.IllegalArgumentException: Either sessionId or session creation parameters (memory and optionally provider, region, projectId, ttl) must be provided`

This confirms that the current Aura Free/Standard tier lacks the memory/session capacity for in-memory graph operations required by GDS algorithms.

## 5. Community Detection Algorithm
Blocked due to infrastructure limitations. Louvain/Leiden require named or anonymous graph projections to run, which are currently unavailable.

## 6. Graph Projection
Unavailable on the current tier. 

## 7. Relationship Types
Intended projection: `['ASSOCIATED_WITH', 'CONNECTED_TO', 'USES']` (Deferred).

## 8. Community Definition
A structural grouping of entities connected tightly via intelligence relationships (Deferred).

## 9. Influential Entity Methodology
Deferred. (Would typically use Degree Centrality or PageRank).

## 10. Bridge Entity Methodology
Deferred. (Would typically use Betweenness Centrality).

## 11. API Implementation
Created `Neo4jCommunityAnalytics` service in `backend/app/ai/neo4j/community.py` and exposed via `GET /api/v1/graph-analytics/communities`. It returns an honest `INFRASTRUCTURE_DEFERRED` state, indicating the need for an infrastructure upgrade to perform graph projections.

## 12. Frontend Implementation
Implemented `CommunityPanel.tsx` integrated into the `IntelligenceWorkspace.tsx`. It features a "Graph Communities" toggle in the analysis toolbar. When clicked, it renders the `INFRASTRUCTURE_DEFERRED` state, explaining the limitation clearly to the investigator without fabricating data.

## 13. Security
- API protected by `JWT` authentication.
- Read-only operations.
- RBAC implemented (`OFFICER`, `EXECUTIVE`, `ADMIN`).
- Zero user-supplied Cypher injection points.

## 14. Empty/Data-Blocked Behavior
The system returns an honest `INFRASTRUCTURE_DEFERRED` status. The UI explicitly states that graph projection capabilities are required and are not available in the current tier.

## 15. Real-Data Validation
Executed tests against the live `f725a8a2` Aura instance verifying that nodes/relationships exist (73/16) but that projections fail. 

## 16. Test Results
The backend correctly catches the inability to project graphs and defers gracefully instead of throwing unhandled 500 exceptions.

## 17. Limitations
Cannot run structural graph algorithms natively on the current database tier.

## 18. Difference Between Concepts
- **Geographic Hotspots (M14.4)**: Geographic concentration of recorded crime locations (e.g., using `ST_ClusterDBSCAN`).
- **Graph Communities (M14.6)**: Structural groups of connected nodes, regardless of geography.
- **Structural Anomalies (Phase 9)**: Irregular graph patterns.
- **Predicted Links (Phase 10)**: Edges likely to form based on topology.

## 19. Final Status
**INFRASTRUCTURE-DEFERRED**

The UI and API readiness layers are implemented, but the core algorithmic execution is deferred due to the verified constraints of the current Neo4j Aura deployment tier. No fake data or proxy algorithms were used to bypass this strict architectural requirement.
