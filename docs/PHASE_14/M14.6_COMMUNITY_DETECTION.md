# Phase 14: M14.6 Community Detection

## 1. Objective
Implement Louvain and Leiden community detection as a reusable LINKRA intelligence capability using Neo4j Graph Data Science (GDS) via Aura Graph Analytics. This capability groups entities based on observed graph connectivity/topology.

## 2. Architecture
The community detection capability follows the fixed LINKRA architecture:
- **Frontend**: `CommunityPanel.tsx` integrated into the `IntelligenceWorkspace` component.
- **API Layer**: Exposes `GET /api/v1/graph/analytics/communities`.
- **Backend Service**: `Neo4jCommunityAnalytics` handles GDS execution and session management.

## 3. Infrastructure Limitation (Aura GDS)
During validation, we attempted to provision an Aura Graph Analytics compute session using the `graphdatascience` Python client. 
- **Result**: `FAILED` to create session (`Unable to retrieve routing information`).
- **Native Cypher Test**: Direct `gds.graph.project` calls failed with an error stating `Either sessionId or session creation parameters ... must be provided`.
- **Status**: **INFRASTRUCTURE_DEFERRED**. The current Neo4j Aura Free/Standard tier does not support GDS in-memory graph projections.

## 4. API & Integration
Rather than fabricating fake results or conflating geographic DBSCAN clusters with graph communities, the system properly implements the `INFRASTRUCTURE_DEFERRED` state across all layers.

### API
- `GET /api/v1/graph/analytics/communities`
- Returns: `status: "INFRASTRUCTURE_DEFERRED"`, an explanatory message, and an empty communities list.
- Secured using existing `RoleChecker(["OFFICER", "EXECUTIVE", "ADMIN"])`.

### Copilot Integration
- Added the `COMMUNITY_LOOKUP` intent.
- Added the `_tool_neo4j_community_lookup` bounded tool to the Copilot Orchestrator.
- When users ask about graph communities (e.g., "What community does Jane Smith belong to?"), the Copilot fetches the deferred state and explains that community detection is blocked by infrastructure limits. Arbitrary user-provided GDS execution is strictly prohibited.

### Frontend Integration
- **Investigation Workspace & Graph Explorer**: Both utilize the `IntelligenceWorkspace` component, which includes a `Communities` toggle.
- **CommunityPanel**: Renders a dedicated alert informing the user of the infrastructure limitation when `isDeferred` is true.
- **Crime Map**: Remains distinct. Spatial clusters (DBSCAN) are strictly treated as geographic hotspots, never graph communities.

## 5. Security & Safety
- **No Arbitrary Cypher**: All GDS calls are predefined in the backend service. Copilot tools do not execute user queries directly.
- **No Database Mutation**: PostgreSQL records and existing Neo4j nodes/relationships remain unchanged.
- **Data Integrity**: The system does not write fake community entities to the database.

## 6. Real Data Validation

- Leiden execution: `INFRASTRUCTURE-DEFERRED`
- Community projection blocked by Neo4j Aura limitations.

## 7. Future Activation
To fully activate Louvain and Leiden community detection:
1. Upgrade the Neo4j instance to AuraDS or a tier that supports the GDS plugin natively.
2. Update the backend `Neo4jCommunityAnalytics` service to remove the deferred return and execute the projection and algorithm.
3. The Copilot, Frontend UI, and API layers are already built and will automatically consume the real community data once available.
