## 1. Current Architecture

```
PostgreSQL (SOURCE OF TRUTH)
    CanonicalEntity → Neo4j :Entity node         [sync: inline on resolution]
    EntityRelationship → Neo4j :[REL_TYPE] edge  [sync: inline on extraction]
                                                  [rebuild: scripts/rebuild_graph.py]
    EntityCandidate → not synced to graph        [evidence via explainability API]
    IngestionJob → not synced to graph           [evidence via explainability API]

Neo4j (PROJECTION LAYER)
    :Entity nodes with stable postgres_entity_id (id property)
    :[REL_TYPE] edges with stable postgres_relationship_id (id property)
    Labels: Entity + {Person|Organization|Location|Vehicle|PhoneNumber|Date|Crime|PoliceStation}

APIs
    GET /graph/entity/{entity_id}         → 0-hop node fetch
    GET /graph/subgraph/{entity_id}       → bounded N-hop neighborhood
    GET /neo4j/network/{suspect_id}       → 2-hop unformatted network
    GET /neo4j/repeat-offenders           → unbounded repeat offender scan
    GET /neo4j/high-risk-networks         → full-graph high-risk scan (RISK)
    GET /neo4j/query (ADMIN POST)         → raw Cypher passthrough (RISK)
    GET /graph_analytics/*                → degree, centrality, shortest path
    GET /graph_anomalies/*                → z-score degree anomaly detection
    GET /graph_predictions/*              → common-neighbor link prediction
    GET /explainability/entity/{id}       → full provenance + graph signals

Frontend
    IntelligenceWorkspace.tsx             → fetches real API data
    NetworkGraph.tsx                      → renders SVG from real nodes/edges
    GraphNodeDetails.tsx                  → calls real /explainability endpoint
```

## 2. Existing Node Model

Nodes are created by `sync_canonical_entity()` in [`intelligence.py`](file:///Users/sharathhn/SIH_26189/ICA_ai/backend/app/ai/neo4j/intelligence.py):

```cypher
MERGE (n:Entity {id: $id})
SET n:<SubLabel>, n += $props
```

| Property | Source | Stored | Notes |
|----------|--------|--------|-------|
| `id` | CanonicalEntity.id (UUID) | ✅ | Stable PostgreSQL identifier |
| `name` | CanonicalEntity.name | ✅ | Display name |
| `entity_type` | CanonicalEntity.entity_type | ✅ | String |
| scalar attributes | CanonicalEntity.attributes (JSON) | ✅ (flattened) | Only `str/int/float/bool` keys |

| `created_at` | BaseModel.created_at | ❌ | **NOT synced** |
| `updated_at` | BaseModel.updated_at | ❌ | **NOT synced** |
| `confidence` | Not in CanonicalEntity | ❌ | No aggregate confidence on canonical |
| `risk_score` | Not in CanonicalEntity | ❌ | Referenced in cypher queries but never set |
| provenance | Not applicable | ❌ | Canonical is already resolved |

**Actual Labels Supported:** Person, Organization, Location, Vehicle, PhoneNumber, Date, Crime, PoliceStation

**Critical Gap:** `risk_score` is referenced in `GET_HIGH_RISK_NETWORK` query but is never populated. Every entity will have `risk_score = 0` (null), making the "High Risk Network" view permanently empty unless manually set.

## 3. Existing Relationship Model

Relationships are created by two paths:

**Path A** — inline in `extractor.py` (`_sync_to_neo4j`):
```cypher
MATCH (a {id: $source_id}), (b {id: $target_id})
MERGE (a)-[r:{REL_TYPE}]->(b)
SET r.confidence = $confidence,
    r.extraction_method = $extraction_method,
    r.event_timestamp = $event_timestamp
```

**Path B** — via `sync_relationship()` in `intelligence.py` (used by `rebuild_graph.py`):
```cypher
MATCH (a:Entity {id: $source_id}), (b:Entity {id: $target_id})
MERGE (a)-[r:{rel_type} {id: $rel_id}]->(b)
SET r += $props
```

### Property Presence Audit

| Property | Path A (extractor.py) | Path B (rebuild_graph.py) | Required |
|----------|----------------------|--------------------------|---------|
| `id` (postgres rel UUID) | ❌ **Missing** | ✅ | Must-have for idempotency |
| `confidence` | ✅ | ✅ | ✅ |
| `extraction_method` | ✅ | ✅ | ✅ |
| `event_timestamp` | ✅ | ✅ | ✅ |
| `source_page` | ❌ **Missing** | ✅ | Important for provenance |
| `source_row` | ❌ **Missing** | ✅ | Important for provenance |
| `ingestion_job_id` | ❌ **Missing** | ❌ **Missing** | Required for full traceability |
| evidence text snippet | ❌ | ❌ | Stored in PostgreSQL only |

### Critical Gap — Path A is NOT Idempotent

In `_sync_to_neo4j` (extractor.py line 216–229), the `MERGE` does NOT include the relationship UUID. This means:
- Running the same ingestion twice creates **duplicate relationships** in Neo4j.
- The `rebuild_graph.py` script **is** idempotent (uses `id` in MERGE).
- The live extraction path **is not**.

## 4. PostgreSQL → Neo4j Synchronization

### Two sync mechanisms exist:

| Mechanism | Trigger | Idempotent | Complete |
|-----------|---------|-----------|---------|
| `sync_canonical_entity()` | Inline on entity resolution | ✅ (MERGE on id) | ⚠️ Partial (no aliases, timestamps) |
| `sync_relationship()` via rebuild_graph.py | Manual script only | ✅ (MERGE on rel.id) | ⚠️ Partial (no ingestion_job_id) |
| `_sync_to_neo4j()` in extractor.py | Inline on extraction | ❌ Not idempotent | ❌ Missing provenance fields |

### Stable Identifier
- **Nodes**: Use `id` property = PostgreSQL `CanonicalEntity.id` (UUID) ✅
- **Edges (rebuild)**: Use `id` property = PostgreSQL `EntityRelationship.id` (UUID) ✅
- **Edges (live extraction)**: No UUID key — not idempotent ❌

## 5. Provenance Traceability

The provenance chain from Neo4j back to source documents is **partially implemented**:

```
Neo4j Relationship
  ↓ r.confidence, r.extraction_method, r.event_timestamp   ✅
  ↓ r.ingestion_job_id                                      ❌ NOT IN NEO4J
EntityRelationship (PostgreSQL)
  ↓ ingestion_job_id, source_page, source_row               ✅
IngestionJob
  ↓ file_name, file_type, source_type                       ✅
EntityCandidate
  ↓ extraction_method, start_offset, end_offset, source_page ✅
  ↓ evidence_text (LLM evidence snippet)                     ✅ (in llm_extractor)
Source Text                                                  ✅ (PostgreSQL)
```

**Explainability API (`/explainability/entity/{id}`) correctly traverses this chain via PostgreSQL.** Neo4j is used only for structural analytics (degree, distribution, anomalies). The evidence storage architecture is correct: evidence text stays in PostgreSQL, not Neo4j.

**Remaining Gap:** Neo4j edges do not carry `ingestion_job_id`, making it impossible to answer "which ingestion created this graph edge?" from the graph layer alone. Must always query PostgreSQL.

### Issues in `get_entity_neighborhood()` ([`intelligence.py:50`](file:///Users/sharathhn/SIH_26189/ICA_ai/backend/app/ai/neo4j/intelligence.py#L50-L56))
- Query uses `[*1..{depth}]` (variable path length) — acceptable for depth ≤ 3
- Uses `LIMIT {max_nodes}` in WITH clause — works
- **No Neo4j index on `entity_type` property** — filter by entity_type is a property scan

### Raw Cypher Passthrough (`/neo4j/query` POST)
- Admin-only ✅
- But accepts **arbitrary user-supplied Cypher** — potential Cypher injection if admin account is compromised
- No query validation or allow-list
- **Risk: HIGH for production**

## 14. Recommended Phase 5 Changes

### P5-1: Critical Bug Fixes (No Design Changes Required)
1. **Fix method name**: `explainability.py:102` calls `get_degree()` — rename to `get_entity_degree()` or add alias.
2. **Fix `_sync_to_neo4j` Cypher injection**: Sanitize `rel.relationship_type` same as `sync_relationship()`.
3. **Fix `_sync_to_neo4j` idempotency**: Add `id` property to MERGE key.
4. **Fix `_sync_to_neo4j` provenance**: Add `source_page`, `source_row`, `ingestion_job_id`.

### P5-2: Graph Schema Hardening
5. **Add startup constraint initialization**: Create `:Entity(id)` UNIQUE constraint and entity_type index at application startup, not only in rebuild script.
6. **Add `risk_score` to CanonicalEntity** (or derive it) and sync to Neo4j nodes.
7. **Add `aliases` list to Neo4j nodes**.
8. **Add `ingestion_job_id` to Neo4j relationship properties**.

### P5-3: Query Safety
9. **Add LIMIT to `FIND_ASSOCIATES`, `FIND_SHARED_VEHICLES`**.
10. **Rewrite `GET_HIGH_RISK_NETWORK`** to use bounded WHERE + LIMIT (cannot be efficient without risk_score index).
11. **Fix `FIND_CRIMINAL_NETWORK`** (returns `path` but nothing uses it — effectively dead code).
12. **Add Cypher query validation** to the `/neo4j/query` POST endpoint (block DDL, DETACH DELETE, etc.).

### P5-4: Frontend Graph Improvements
13. **Fix node type mapping** in `NetworkGraph.tsx` — map `person → suspect`, `phonenumber → phone`, etc.
14. **Add graph drill-down**: on node click, navigate to `/graph/subgraph/{id}`.
15. **Replace `IntelligenceFeedTicker` mock data** with real alerts/events API.

### P5-5: Test Coverage
16. **Add `tests/test_graph_sync.py`**: idempotency, duplicate prevention, provenance fields.
17. **Add `tests/test_graph_queries.py`**: neighborhood bounds, empty graph, anomaly detection thresholds.
