# M0.4 Frontend Audit

## 1. Objective
To perform a read-only, evidence-based audit of the existing ICA_AI frontend. The goal is to document the existing architecture, UI flows, and API integrations, and to perform a gap analysis against the SIH26189 target requirements to determine what can be reused, modified, or must be replaced.

## 2. Scope
- **Frontend Framework**: Next.js 16 (React 19)
- **Directory**: `frontend/`
- **Key Files**: `package.json`, `src/app/*`, `src/components/*`, `src/hooks/*`, `src/services/*`, `src/store/*`
- **Analysis Focus**: Architecture, routes, component reusability, UI/UX against SIH26189, and frontend technical debt.

## 3. Frontend Architecture
- **Framework**: Next.js 16.2.7 utilizing the App Router (`src/app`).
- **Styling**: Tailwind CSS v4, `shadcn/ui` utilities (`clsx`, `tailwind-merge`), and Framer Motion for animations.
- **State Management**: Zustand (`src/store/authStore.ts` with `localStorage` persistence).
- **Data Fetching**: `@tanstack/react-query` and `axios` are installed, but heavily underutilized. Most components use raw `fetch()` directly in `useEffect`.
- **Maps**: `maplibre-gl` and `react-map-gl`.
- **Icons**: `lucide-react`.

Evidence:
- `frontend/package.json`
- `frontend/src/app/layout.tsx`

## 5. Component Inventory

### REUSE
- `DashboardLayout.tsx`: The primary shell (sidebar + topnav) is well-structured.
- `GlobalSearchBar.tsx`: Standard UI component for global querying.
- `NetworkGraph.tsx`: Foundational component for Neo4j visualization.
- `ui/button.tsx`: shadcn baseline.

### MODIFY
- `FIRWorkspace/*`: Good layout for document processing, but hardcoded to "BLR-FIR-2026-0399". Needs to be genericized for dynamic ingestion workflows.
- `Predictive/*`: Needs to be stripped of hardcoded KCIA terminology and hooked to actual ML backends.
- `ExecutiveDashboard/*`: Contains hardcoded Karnataka maps/polygons. Must become state-agnostic.

### REPLACE
- `Login` OTP Flow: The OTP check hardcodes `123456` and lacks real MFA backend support.
- Hardcoded SVG Maps: E.g., the Karnataka map in `src/app/dashboard/page.tsx` (`<svg viewBox="0 0 200 300"...>`).

### NEW
- `DataIngestionPanel`: UI for uploading PDFs/CSVs and showing parser status.
- `EntityResolutionReview`: UI to accept/reject potential entity merges.

## 6. User Flow Audit

### Authentication Flow
```text
/ (page.tsx) Check isAuthenticated
    ↓ (If false)
/login
    ↓ User enters Badge + Password
API Request (authService.login)
    ↓ Response (JWT)
State Update (authStore.ts saves to localStorage)
    ↓
Simulated OTP Step (Hardcoded 123456)
    ↓
/dashboard
```
*Gap*: OTP step is completely fake. JWT is not being consistently attached to subsequent requests.

### FIR Intelligence Flow (e.g. `/fir-workspace`)
```text
/fir-workspace
    ↓ Hardcoded firId ("BLR-FIR-2026-0399")
Components (AIFIRSummary, ExtractedEntitiesPanel, NetworkGraph)
    ↓
Raw fetch() to http://localhost:8000/api/v1/crimes/BLR-FIR-2026-0399/summary (NO AUTH HEADER)
    ↓
State Update
    ↓
Renders Mock Data
```
*Gap*: Hardcoded IDs, missing JWT headers, tight coupling to specific incident formats.

## 7. Frontend/API Integration Audit

Evidence shows massive technical debt in API integrations. 
`grep` revealed ~30 instances of raw `fetch("http://localhost:8000/api/v1/...")` scattered directly inside React components (`useEffect`).

| Frontend Component | Endpoint | Auth Attached | SIH26189 Status |
| ------------------ | -------- | ------------- | --------------- |
| `useCrimes.ts` | `/crimes` | Yes (Bearer token) | Partially aligned |
| `auth.service.ts` | `/auth/login` | N/A | Aligned |
| `system-health/page.tsx` | `/system-health/*` | **No** | Needs centralized client |
| `AIFIRSummary.tsx` | `/crimes/{id}/summary` | **No** | Needs centralized client |
| `FIRTimeline.tsx` | `/crimes/{id}/timeline` | **No** | Needs centralized client |
| `Dashboard/page.tsx`| `/neo4j/high-risk-networks`| **No** | Needs centralized client |

*Critical Gap*: Because these endpoints require authentication on the backend, they will fail in production or if the backend enforces its RBAC strictly. The frontend expects an unauthenticated backend.

## 9. Reusable Frontend Functionality

The following should be preserved to accelerate development:
1. **Routing & Layout Structure**: The Next.js App Router setup and `DashboardLayout.tsx` are excellent and state-of-the-art.
2. **State Management**: `zustand` setup in `authStore.ts` is solid.
3. **NetworkGraph Component**: Visualizing nodes/edges is already implemented.
4. **Tailwind / UI Aesthetics**: The dark-mode, intelligence-platform styling perfectly fits the hackathon's vibe. Keep the CSS/shadcn configuration.

## 10. Components Requiring Modification

1. **All API Integrations**: Replace raw `fetch` calls with an `axios` interceptor that injects the JWT token and uses `NEXT_PUBLIC_API_URL`.
2. **Dashboard Widgets**: Remove hardcoded KSP/Karnataka/KCIA text. Use generic terms (e.g., "State Intelligence" instead of "Karnataka Crime Intelligence").
3. **FIR Workspace**: Parameterize the page so it takes a document ID from the URL instead of hardcoding `BLR-FIR-2026-0399`.

## 11. Components Requiring Replacement

1. **Hardcoded Maps**: The SVG map in `src/app/dashboard/page.tsx` must be removed and replaced with a `maplibre-gl` implementation driven by real geographic data.
2. **Fake OTP Flow**: Remove the fake OTP step in `src/app/login/page.tsx` or wire it to a real backend if MFA is required.

## 12. New Frontend Functionality Required

1. **Ingestion Hub (`/ingestion`)**: Drag-and-drop UI for PDFs/CSVs to feed the multi-source data ingestion requirement.
2. **Entity Resolution Workspace (`/resolution`)**: A UI for investigators to approve/reject potential entity merges (e.g., "Are Ravi K. and Ravi Kumar the same person?").

## 13. UI/UX Gap Analysis
- **Navigation**: Excellent, highly modular.
- **Role-based Views**: The UI allows selecting a role at login but doesn't actually hide/show sidebar elements based on that role securely (it just displays the role string).
- **Empty/Loading States**: Needs improvement. Currently, if an API fails (which they will due to auth), the UI often crashes or silently renders nothing.

## 14. Frontend Technical Debt

1. **Raw Fetch Calls**: 30+ instances of `fetch("http://localhost:8000...")` bypassing auth and env vars.
2. **State Coupling**: Using Next.js App Router but fetching data heavily in `useEffect` on the client side, causing waterfalls. React Query is installed but barely used (only in `useCrimes.ts`).
3. **Hardcoded Identifiers**: `BLR-FIR-2026-0399`, `00000000-0000-0000-0000-000000000000` (used in predictive endpoints).
4. **Mocked Security**: The login page simulates a 1.2s "Cryptographic Handshake".

## 16. Recommended Future Implementation Order
1. **Tech Debt**: Setup `axios` instance with JWT interceptors. Replace all raw `fetch` calls.
2. **De-branding**: Remove "Karnataka" and "KSP" hardcoded strings.
3. **Routing Fixes**: Parameterize `fir-workspace` and other detail pages.
4. **New Features**: Build the Data Ingestion UI to allow feeding the backend pipeline.

## 18. Final Findings
The ICA frontend provides an exceptionally polished, hackathon-ready UI (Tailwind + Dark Mode) that perfectly matches the SIH26189 "Intelligence Platform" aesthetic. The component architecture is solid. 

However, the **integration layer is entirely broken**. The frontend relies on hardcoded `localhost:8000` fetches, bypasses JWT authentication for almost all components, and hardcodes entity IDs (like FIR numbers) directly into the views. The immediate priority during implementation must be establishing a centralized, authenticated Axios client and replacing the raw `fetch` calls, followed by building the missing Data Ingestion UI.
