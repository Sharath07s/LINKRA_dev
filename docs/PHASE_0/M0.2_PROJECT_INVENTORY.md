## 1. Inventory Objective

This document represents a read-only inventory of the existing ICA_AI repository before executing any SIH transformation changes. The goal is to document the existing architecture, files, endpoints, and implementations.

## 3. High-Level Architecture

The architecture observed from code inspection consists of:
```
Frontend (Next.js App Router)
   ↓
API (FastAPI REST & WebSockets)
   ↓
Backend Services (Predictive, RAG, Core Entities)
   ↓
Databases (PostgreSQL with pgvector, Neo4j, Redis) / External AI Providers (OpenAI, Gemini, Anthropic, Groq, DeepSeek)
```

## 8. PostgreSQL Inventory

- **Models**: Includes `CrimeType`, `DocumentChunk`, `User`, `Role`, `Alert`, etc.

- **Relationships**: Extensive use of SQLAlchemy `relationship`.

- **Seeds**: `backend/scripts/seed_database.py`.
- **Configuration**: SQLAlchemy URI configured via `Settings` pulling from environment variables.

## 9. Neo4j Inventory

- **Nodes**: `Suspect`, `Crime`, `Vehicle`, `Location`, `PhoneNumber`, `PoliceStation`, `District`.
- **Relationships**: `INVOLVED_IN`, `USED`, `INVOLVES`.
- **Cypher files**: Present in `backend/app/ai/neo4j/cypher_queries.py`.
- **Graph builder**: `backend/scripts/build_graph.py`.
- **Connection layer**: `backend/app/db/neo4j.py` using `neo4j` Python driver.

## 10. Redis Inventory

- **Connection**: `REDIS_URL` in config.
- **Usage**: Added as a package dependency (`redis==8.0.0`) but no substantial direct integration logic was statically found within the main application services during this read-only inspection.

## 11. RAG Inventory

- **Document ingestion**: `PyPDFLoader` in `backend/scripts/ingest_fir_pdfs.py`.
- **Chunking**: `RecursiveCharacterTextSplitter` (chunk_size=1000, overlap=200).
- **Embedding**: HuggingFace `all-MiniLM-L6-v2` (`langchain_huggingface`).
- **Vector storage**: PostgreSQL with `pgvector` (`DocumentChunk` model).
- **Similarity search**: Handled natively by PGVector `cosine_distance` in `backend/app/ai/rag/vector_search.py`.
- **Context retrieval & LLM**: Executed via standard AI endpoints calling `VectorStore.semantic_search`.

## 12. AI/ML Inventory

- **Modules Present**: `intents`, `neo4j` (intelligence), `query_planner`, `rag`, `workflows` (FIR extraction).
- **LLM Integrations**: Multiple providers defined in `provider.py` (OpenAI, Gemini, Claude, DeepSeek, Groq) with a `FallbackManager`.
- **Predictive Analytics**: Stubs/Implementations exist for forecasting, hotspots, network growth, and recidivism in `backend/app/services/predictive/`.
- **LangChain/LangGraph**: Core orchestration dependencies are present.

## 20. Architecture Observations

- **Modular Backend**: Heavily decoupled architecture across numerous services and domain routers.
- **Mixed Integrations**: Frontend blends actual backend endpoint calls alongside hardcoded fallbacks (e.g., hardcoded FIR ID parameters).
- **Complex AI Routing**: A `FallbackManager` orchestrates multiple AI providers sequentially.
- **Rich Databases**: Architecture mandates running three persistent layers (PostgreSQL, Neo4j, Redis) effectively.
