## 1. Audit Objective

This document is a deep, read-only audit of the ICA_AI FastAPI backend. The objective is to understand:

1. What API endpoints exist and how they work.
2. What services implement them and what real logic exists.
3. How PostgreSQL, Neo4j, pgvector, and Redis are used.
4. How authentication and RBAC are implemented.
5. How AI, LLM, and RAG pipelines work.
6. How predictive analytics are implemented (algorithm vs ML model).
7. What is real implementation vs. placeholder/hardcoded logic.
8. What is Karnataka/KSP-specific and tightly coupled.
9. What components are candidates for SIH reuse.

**This is an audit only. No code was modified.**

## 7. API Data Flow

### 7.1 POST /api/v1/chat/ — Complete Trace

```
Request: ChatQuery {query: string}
  ↓
deps.get_current_active_user() → JWT decode → PostgreSQL User lookup
  ↓
IntentEngine.extract_intent(query)
  └─ LangChain PromptTemplate → FallbackManager.execute_with_fallback(structured_schema=IntentResponse)
       └─ Sequence: Groq → Gemini → OpenAI → DeepSeek
  └─ On failure: _keyword_intent(query) [hardcoded KEYWORD_MAP + Karnataka district list]
  → Returns: {intent, crime_type, district, time_frame}
  ↓
QueryPlanner.execute_intent(db, intent_data)
  └─ crime_search → SQLAlchemy: Crime JOIN CrimeType JOIN District
  └─ suspect_search → SQLAlchemy: Suspect ORDER BY risk_score
  └─ hotspots → SQLAlchemy: Crime+District GROUP BY district
  └─ suspect_network → Neo4jIntelligenceService.get_suspect_network() [hardcoded fallback: "S123"]
  └─ criminal_cluster → Neo4jIntelligenceService.get_high_risk_network()
  └─ general → COUNT aggregates across 4 tables
  ↓
[If crime_search or suspect_search]:
VectorStore.semantic_search(query, top_k=3)
  └─ HuggingFaceEmbeddings("all-MiniLM-L6-v2").embed_query() → float[384]
  └─ pgvector cosine_distance query on document_chunks
  ↓
FallbackManager.execute_with_fallback(summarization_prompt, temperature=0.3)
  └─ Prompt includes: intent, DB records (JSON), RAG chunks
  └─ On full LLM failure: _format_raw_data() → markdown table fallback
  ↓
Return: ChatResponse {message, provider, intent, structured_data, record_count}
```

## 8. Authentication Architecture

**Files:** `backend/app/core/security.py`, `backend/app/api/deps.py`, `backend/app/api/v1/auth.py`

### Login Flow
```
POST /auth/login (badge_number as username, password)
  → db.query(User).filter(badge_number == username, is_deleted == False)
  → bcrypt.checkpw(plain, hash)
  → jose.jwt.encode({exp, sub: user.id, type: "access"}, SECRET_KEY, HS256)
  → jose.jwt.encode({exp: 30d, sub: user.id, type: "refresh"}, SECRET_KEY, HS256)
  → Return {access_token, refresh_token, token_type: "bearer"}
```

### Protected Endpoint Flow
```
Authorization: Bearer <token>
  → oauth2_scheme extracts token
  → jose.jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
  → extract sub (user_id), assert type == "access"
  → db.query(User).filter(id == user_id, is_deleted == False)
  → assert user.is_active == True
  → Route handler executes
```

### Gaps
- No logout/token blacklisting endpoint.
- No password reset endpoint.
- MFA: Comment stub only (`# MFA readiness check can be inserted here`).
- Default `SECRET_KEY = "your-secret-key-for-dev"` in config. **Hardcoded insecure default.**
- Login identifies officers by `badge_number` — Karnataka/KSP-specific field.

## 9. RBAC Architecture

**File:** `backend/app/api/deps.py`

### Implementation
```python
class RoleChecker:
    def __init__(self, allowed_roles: List[str]):
        self.allowed_roles = allowed_roles
    def __call__(self, user: User, db: Session):
        role = db.query(Role).filter(Role.id == user.role_id).first()
        if not role or role.name not in self.allowed_roles:
            raise HTTPException(status_code=403)
        return user
```

## 13. RAG Architecture

### Document Ingestion (`scripts/ingest_fir_pdfs.py`)
```
PDF files (./data/pdfs/*.pdf)
  ↓ PyPDFLoader (langchain_community)
  ↓ RecursiveCharacterTextSplitter (chunk_size=1000, overlap=200)
  ↓ HuggingFaceEmbeddings("all-MiniLM-L6-v2").embed_query() → float[384]
  ↓ DocumentChunk(source_id, content, metadata_json, embedding) → PostgreSQL
```
**Supported formats:** PDF only. **Ingestion via CLI script only — no API endpoint.**

### Similarity Search (`ai/rag/vector_search.py`)
```
Query string
  ↓ HuggingFaceEmbeddings("all-MiniLM-L6-v2").embed_query() → float[384]
  ↓ SELECT DocumentChunk ORDER BY embedding.cosine_distance(query_embedding) LIMIT 5
  ↓ Return [{doc_id, content, metadata, similarity: 1.0 - distance}]
```

### RAG in Chat Pipeline
- Invoked only for `crime_search` and `suspect_search` intents.
- Not invoked for hotspots, trends, networks, or general.
- top_k=3 in chat endpoint.

### Bug Found
- `/system-health/rag` endpoint (system_health.py line 76) reports `embedding_model: "text-embedding-gecko"`.
- Actual embedding model is `all-MiniLM-L6-v2`. This is an incorrect health check annotation.

## 16. Predictive / Analytics Architecture

### 16.1 CrimeForecaster
**Algorithm:** Weighted Moving Average (WMA)
```
predicted = (p1*0.5) + (p2*0.3) + (p3*0.2)   [30d, 30-60d, 60-90d periods]
confidence = min(total/100, 0.7) + stability_bonus
```
**No ML model. No training data. No scikit-learn/XGBoost.**

### 16.2 HotspotPredictor
**Algorithm:** Spatial acceleration threshold
```
if rec_vol >= 5 AND growth > 50% in 14d vs prior 14d:
    → predicted hotspot (confidence: 0.85 if vol>15 else 0.65)
```
**No spatial ML. No KDE. No ML library.**

### 16.3 RecidivismEngine
**Algorithm:** Additive weighted scoring
```
probability = crimes_count * 0.15 (base, capped 0.60)
           + high_severity_crimes * 0.10 (capped 0.20)
           + degree_centrality * 0.05 (capped 0.15)
```
Neo4j KNOWS degree included. **Manually assigned weights. No ML model.**

### 16.4 NetworkGrowthEngine
**Algorithm:** Preferential attachment heuristic
```
predicted_new_edges = max(1, int(degree * 0.2))  [20% growth assumed]
confidence = 0.82  [hardcoded]
```
**No graph ML. No link prediction algorithm. Simple degree heuristic.**

### Summary

| Engine | Algorithm | ML? | Libraries |
|---|---|---|---|
| CrimeForecaster | Weighted Moving Average | ❌ No | SQLAlchemy, datetime |
| HotspotPredictor | Acceleration threshold | ❌ No | SQLAlchemy, datetime |
| RecidivismEngine | Additive weighted scoring | ❌ No | SQLAlchemy, Neo4j driver |
| NetworkGrowthEngine | Preferential attachment heuristic | ❌ No | Neo4j driver |

## 17. Alerts / WebSocket Architecture

### Alert Trigger Mechanism
Alert generation is **synchronous and request-driven**: calling `GET /alerts/` executes `AlertEngine.evaluate_all()` inline. No background scheduler or cron job exists.

### Alert Rule Types

| Type | Source | Trigger |
|---|---|---|
| Crime Spike | PostgreSQL | recent > 5 AND 50%+ growth in 7d |
| Hotspot Escalation | PostgreSQL | volume >= 20 crimes in 7d |
| Repeat Offender | PostgreSQL | suspect linked to >= 3 crimes |
| Emerging Network | Neo4j | Suspect degree >= 5 (KNOWS) |
| Predictive Hotspot | HotspotPredictor | confidence > 0.75 |
| Predictive Network | NetworkGrowthEngine | expansion_risk == HIGH |
| Model Drift | MonitoringSummary | volume drift > 30% |
| Forecast Degradation | MonitoringSummary | trend == "Degrading" |
| Low Reliability | MonitoringSummary | reliability_score < 60 |

**Deduplication:** Same alert title not re-created within 24 hours.

### Two Independent WebSocket Implementations

1. **`ws.py` `/ws/notifications`**: Simple in-memory broadcast. Echoes received text to all clients. Not connected to EventBus. No authentication. No channel segmentation.

2. **`realtime.py` `/realtime/ws/{channel}`**: Advanced channel-segmented implementation. Bridges EventBus events to clients. 5 channels. No authentication.

**Finding:** Two separate WebSocket implementations with no cross-connection. The simpler `ws.py` doesn't receive EventBus events.

## 27. M0.3 Conclusion

The ICA_AI backend is a **substantial, multi-domain FastAPI application** with approximately 90 API endpoints across 21 routers. The architecture reflects significant engineering effort.

**Genuine strengths:**
- Multi-provider LLM fallback architecture is production-quality and provider-agnostic.
- pgvector RAG pipeline is architecturally sound.
- EventBus → WebSocket streaming pipeline is well-designed.
- Neo4j integration with parameterized Cypher queries is functional.
- Heuristic predictive engines produce explainable, evidence-based outputs.
- SQLAlchemy model hierarchy with shared mixins is clean.

**Key concerns:**
- Numerous critical unauthenticated endpoints (Neo4j, infrastructure, WebSockets).
- Several major features are confirmed placeholders or hardcoded mock data (FIR entities, timeline, fusion briefing, LangGraph workflow).
- All "ML" is heuristic/statistical algorithms — no trained models exist.
- System is architecturally and textually coupled to Karnataka (KCIA/KSP identity, districts, coordinates, language references, prompts).
- Redis is declared but unused. In-process EventBus cannot scale horizontally.

**SIH transformation readiness:** The architecture pattern and core infrastructure are reusable. The specific logic, prompts, seeded data, and system identity must all be reworked for state-agnostic, SIH-compliant operation.
