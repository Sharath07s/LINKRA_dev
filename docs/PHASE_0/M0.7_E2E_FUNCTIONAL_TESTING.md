# M0.7 — End-to-End Functional Testing

## 1. Objective
Perform a read-only, evidence-based, end-to-end functional test of the existing ICA_AI application. The purpose is to determine what actually works at runtime before any SIH26189 implementation begins, verifying the findings from M0.3 to M0.6.

## 2. Testing Scope
- Application Startup (Frontend, Backend, Databases)
- Core Workflows (Authentication, FIR Workspace, Graphs)
- API Endpoint Functionality
- AI/ML Pipeline Execution (Copilot, RAG, Predictive Engines)

## 3. Test Environment
- **OS**: macOS (Sandbox Environment)
- **Node**: v22+
- **Python**: 3.13
- **Network Constraints**: The sandbox environment inherently blocks outgoing TCP connections to local database ports (5432, 7687, 6379) and does not possess a natively running Docker daemon accessible to the test agent.

**Evidence**: 
- `uvicorn app.main:app` successfully bound to port 8000 and served the `/health` endpoint.
- `npm run dev` started the Next.js server on port 3000, but any HTTP request (e.g. `/login`) caused a Turbopack panic (`node process exited before we could connect to it`) returning HTTP 500.
- `psql` and `docker` are unavailable/blocked in this environment, preventing local database spin-up.

## 5. Authentication Testing
**Trace**: User → Login → Backend → JWT
- **Behavior**: `POST /api/v1/auth/login` returns **HTTP 500 Internal Server Error**.
- **Root Cause**: The backend attempts to query the `users` table via SQLAlchemy (`db.query(User).filter(...)`). Since the PostgreSQL connection is blocked, the database session fails, preventing token generation.
- **Status**: **BLOCKED**

## 6. RBAC Testing
- **Behavior**: All protected endpoints (e.g., `/api/v1/crimes/*`, `/api/v1/predictive/*`) return **HTTP 401 Unauthorized** with `{"detail":"Not authenticated"}`.
- **Root Cause**: `get_current_user` dependency requires a valid JWT and performs a database lookup. Without a valid login mechanism or database, RBAC cannot be bypassed.
- **Status**: **BLOCKED**

## 7. Core Crime/FIR Workflow

- **Root Cause**: Frontend crashing due to Next.js/Turbopack compatibility issues in the environment, and backend crime APIs rejecting requests with 401 Unauthorized.
- **Status**: **BLOCKED**

## 20. Root Cause Analysis
1. **Frontend**: Next.js 16.2.7 Turbopack is panicking when compiling `globals.css` in this specific execution environment. 
2. **Backend / APIs**: The application strictly enforces dependency injection for database sessions (`get_db`) and authentication (`get_current_active_user`) on almost all routes. Without a live database, the entire API surface becomes untestable.

## 25. Final Assessment
The M0.7 E2E Functional Test concludes that the **ICA_AI backend framework is structurally sound and starts successfully**, but its tight coupling to PostgreSQL for authentication prevents any meaningful runtime testing of its AI/ML or data pipelines when the database is unavailable. 

The **frontend is currently non-functional** in this environment due to a Next.js compilation crash. 

As a result, the findings from M0.3, M0.4, M0.5, and M0.6 remain the authoritative, code-verified baseline for the SIH26189 conversion.
