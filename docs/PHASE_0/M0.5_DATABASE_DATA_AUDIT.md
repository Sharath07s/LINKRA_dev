## 4. PostgreSQL Architecture

**FACT** — Evidence from `backend/app/db/session.py`:
- **Session management**: Standard SQLAlchemy session factory, dependency-injected via `get_db()`.
- **Connection URI**: Built from env variables (`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_SERVER`, `POSTGRES_PORT`, `POSTGRES_DB`).
- **Default DB name**: `kcia` (KSP-specific — must be renamed for SIH).
- **ORM style**: SQLAlchemy 1.x query style (`db.query()`) throughout, compatible with 2.x.
- **Extensions required**: `pgvector` (`vector` extension).

**FACT** — Base model mixins applied universally (`backend/app/models/base.py`):
- `TimestampMixin`: `created_at`, `updated_at`
- `SoftDeleteMixin`: `is_deleted`, `deleted_at`
- `AuditMixin`: `created_by`, `updated_by`
- Primary key: `UUID(as_uuid=True)` via `uuid.uuid4`

**GAP** — Alembic migrations are largely stubs. `5f09a129d9b5_initial_schema.py` has empty `upgrade()` and `downgrade()` bodies (just `pass`). The full schema is managed by SQLAlchemy's `Base.metadata.create_all()` in the seed script (`drop_and_create_tables()`), **not via Alembic migrations**. This is a significant operational gap for controlled schema evolution.

## 8. PostgreSQL ↔ Neo4j Relationship

**FACT** — Evidence from `backend/scripts/build_graph.py`:

Synchronization is **one-directional, manual, and script-driven**:

```text
PostgreSQL (authoritative source of truth)
        │
        │  Manual CLI only: python build_graph.py --reset
        ▼
Neo4j Graph (derived, secondary store — potentially stale)
```

| Aspect | Finding |
| ------ | ------- |
| Source of truth | PostgreSQL is authoritative for all entities |
| Sync mechanism | One-time CLI script only. No automatic sync on data changes. |
| Shared IDs | PostgreSQL UUIDs are copied as `id` properties to Neo4j nodes |
| Bi-directional sync | Does NOT exist |
| Auto-sync on create | `POST /crimes/` creates PostgreSQL record only. No Neo4j node created automatically. |
| Stale graph risk | **HIGH** — any new crime or suspect added via API will NOT appear in Neo4j until `build_graph.py` is re-run manually |

**GAP**: The `ASSOCIATED_WITH` relationship between suspects is derived algorithmically (co-offender pattern) — it exists only in Neo4j and has no PostgreSQL equivalent.

## 22. Protected Data Assets

The following data structures are sound and must NOT be casually rewritten without explicit justification:

1. **`BaseModel` mixin pattern** — `TimestampMixin`, `SoftDeleteMixin`, `AuditMixin`. All new tables must inherit it.
2. **UUID primary keys** — Consistent across all models. Do not change to integer keys.
3. **`document_chunks` + pgvector(384)** — The vector dimension is matched to `all-MiniLM-L6-v2`. Changing this would require re-embedding all documents.
4. **`crime` → `crime_type` → `district` → `station` relational chain** — Solid normalized structure.
5. **`suspects` ↔ `crimes` via `suspect_crimes` join table** — Correct M2M modeling; preserves role per suspect per crime.
6. **Neo4j `ASSOCIATED_WITH` derivation pattern** — Deriving suspect-suspect edges from co-offending is architecturally sound.
7. **`EventAuditLog` persistence** — Valuable operational audit trail; do not remove.
8. **`FallbackManager` LLM abstraction** — Multi-provider resilience is a key strength; preserve the abstraction.

## 23. Critical Findings

1. **ZERO REAL DATA** — The entire database is synthetic seed data. No real crime records have ever been processed.

2. **BROKEN FIR DETAIL APIs** — `GET /crimes/{id}`, `GET /crimes/{id}/entities`, `GET /crimes/{id}/timeline` all return **hardcoded mock responses** regardless of what ID is passed. These are the most-used endpoints by the frontend FIR Workspace.

3. **NO EXTRACTION PIPELINE** — The LangGraph FIR extraction workflow (`fir_extraction.py`) is completely mocked. It returns hardcoded strings. NLP extraction is the core SIH26189 P0 requirement, and it has **zero real implementation**.

4. **NO INGESTION API** — Documents can only be ingested via CLI (`ingest_fir_pdfs.py`). There is no API endpoint and no UI to ingest documents. This is the first SIH26189 P0 requirement.

5. **STALE NEO4J BY DESIGN** — No automatic synchronization between PostgreSQL writes and Neo4j. Every new crime added via API is invisible to the graph layer until a manual rebuild script is run.

6. **MISSING ENTITY RESOLUTION LAYER** — There is no `canonical_entity`, `entity_merge`, or candidate scoring table. Entity deduplication has no data infrastructure.

7. **NO EVIDENCE PROVENANCE** — No model links AI-generated insights or graph edges back to source document text spans. All AI claims are unverifiable.
