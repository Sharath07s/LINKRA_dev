> **Phase 0 | Milestone M0.6 | Date: 2026-08-25**

---

## 1. Objective
Perform a read-only, evidence-based audit of every AI, ML, NLP, LLM, predictive, recommendation, intelligence, graph-analysis, and automated reasoning capability in ICA_AI. 

The primary goal is to distinguish between genuine AI/ML implementation, rule-based heuristics, mocked/hardcoded fallbacks, and completely missing functionality required for SIH26189.

## 4. AI/ML Implementation Reality Classification

- **RAG Vector Search**: **REAL**. Valid PGVector integration using Langchain and HuggingFace.
- **LLM Abstraction (FallbackManager)**: **REAL**. Good routing between Groq, Gemini, OpenAI, Claude, DeepSeek.
- **Intent Extraction**: **REAL**. Uses LLM with structured output to parse `crime_type`, `district`, `time_frame`.
- **Crime Forecasting**: **RULE-BASED**. No ML model. Uses simple 30/60/90 day Weighted Moving Average (WMA).
- **Hotspot Prediction**: **RULE-BASED**. No spatial ML. Compares 14-day vs 28-day volume in SQL.
- **Recidivism Scoring**: **RULE-BASED**. Simple integer math (e.g., probability += 0.15 * crimes).
- **FIR Extraction (NLP)**: **MOCKED**. Returns hardcoded JSON (`"suspects": ["Unknown Male"]`).
- **Graph AI Traversal**: **MOCKED**. `QueryPlanner` hardcodes IDs like `S123`, `KA01AB1234` for all network queries.
- **Network Growth Engine**: **BROKEN**. Cypher query looks for `KNOWS` edge which does not exist in the Neo4j build script.
- **Entity Resolution**: **MISSING**. No deduplication, similarity scoring, or canonical entity merging exists.

## 6. AI Copilot Audit

1. `IntentEngine`: Extracts intent using LLM. (REAL)
2. `QueryPlanner`: Executes query. (Tabular = REAL, Graph = **MOCKED** due to hardcoded kwargs).

4. `Summarization`: LLM generates markdown response. (REAL).

**Critical Findings**:
- **GAP**: Conversational context is **not persisted**. The API accepts a single `query` and returns a `response`. It has no memory of previous messages.
- **UNUSED**: `ai_conversations` and `ai_messages` exist in PostgreSQL ORM, but `grep` confirms they are **never imported or queried** anywhere in the backend code. 
- **MOCKED**: If the user asks for a network graph, `planner.py` uses `S123` or `FIR-2025-441` unconditionally. It does not extract the actual ID from the prompt.

## 11. Anomaly / Risk / Scoring Audit

**Trace of `AlertEngine`**:
Runs entirely on rule-based SQL aggregation heuristics:
- **Crime Spikes**: `if recent > 5 and growth > 50%` → CRITICAL
- **Hotspot Escalation**: `if count >= 20 in 7 days` → HIGH
- **Repeat Offender**: `if count >= 3 crimes` → MEDIUM
- **Model Health**: `if MAPE > threshold` → HIGH

**Status: RULE-BASED**
The engine generates actionable alerts but uses no statistical anomaly detection algorithms (e.g., Isolation Forest).

## 12. Knowledge Graph Intelligence Audit

**FACT**: Neo4j is used strictly as a traversal database, not an algorithmic Graph Data Science (GDS) tool.

**GAP**: Cypher queries in `cypher_queries.py` perform basic pattern matching (`[*1..2]`). No graph algorithms (PageRank, Louvain, Node2Vec) are implemented.
**BROKEN**: Queries frequently reference relationships like `KNOWS` or `PARTICIPATED_IN`. The ingestion script (`build_graph.py`) only creates `ASSOCIATED_WITH` and `INVOLVED_IN`. Therefore, several graph intelligence alerts silently fail.

## 17. AI/ML Reuse Strategy

- **KEEP**: `FallbackManager` (excellent multi-LLM router), PGVector schema (`document_chunks`).
- **ADAPT**: `IntentEngine` (remove Kannada/Karnataka references), `AlertEngine` (generalize rules).
- **REFACTOR**: `QueryPlanner` (remove hardcoded IDs, properly parse entities to use as parameters), Neo4j `cypher_queries.py` (sync relation names with ingestion script).
- **BUILD NEW**: NLP Entity Extractor, Entity Resolution Engine, Automated Neo4j Sync, Evidence Provenance Citations, Chat History endpoints.
- **REMOVE**: `fir_extraction.py` mock JSON.

---

## 18. AI/ML Technical Debt

1. **Disconnected Database Models**: `ai_conversations` and `ai_messages` are strictly schema. The Copilot has amnesia.
2. **Graph Schema Drift**: Queries look for `KNOWS` while ingestion creates `ASSOCIATED_WITH`.
3. **Hardcoded Copilot Fallbacks**: A query for "suspect network" always queries suspect ID `S123`.
4. **Synchronous LLM Calls**: Complex fallback LLM chains run synchronously in API requests, risking timeouts.

## 21. Critical Findings

1. **THE COPILOT IS PARTIALLY MOCKED**: While Tabular/SQL and RAG lookup work, any network/graph question uses hardcoded IDs (`S123`, `FIR-2025-441`) and ignores the actual suspect named by the user.
2. **NLP EXTRACTION DOES NOT EXIST**: The single most important SIH feature (reading an FIR and extracting entities) is entirely fabricated via a hardcoded JSON string.
3. **NO ENTITY RESOLUTION**: ICA has absolutely zero deduplication capability.
4. **GRAPH AI IS BROKEN**: Neo4j intelligence queries rely on relations (`KNOWS`) that the database builder never creates.
5. **ZERO PREDICTIVE ML**: All "forecasting" and "recidivism" scores are simple mathematical rules (e.g. +15% probability per crime), not trained models.

---

## 22. Final Assessment

1. **What AI/ML capabilities actually exist?** RAG (pgvector), LLM Intent Extraction, LLM Summarization, Rule-based Forecasting.
2. **Which are real?** RAG, LLM Routing, Intent Extraction.
3. **Which are mocked?** FIR Entity Extraction, Graph Copilot Planning.
4. **Which are rule-based?** Forecaster, Hotspot Predictor, Recidivism, Alert Engine.
5. **Which are broken?** Network Growth Engine, Graph Alerts (schema drift).
6. **Which are unused?** Chat History DB models (`ai_conversations`).
7. **Which AI outputs are persisted?** Only RAG embeddings and Alerts.
8. **What capabilities are completely missing?** Entity Extraction, Entity Resolution, Evidence Provenance, Ingestion API.
9. **What must Phase 1/2/3 eventually address?** We must build real NLP extraction and entity deduplication pipelines immediately, as they are SIH26189 P0 requirements and currently do not exist.
