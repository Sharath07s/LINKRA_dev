## Data Flow

```
PDF / CSV / JSON / TXT file
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│   POST /api/v1/ingestion/upload (JWT-authenticated)     │
│                                                         │
│   1. await file.read() → validate_file()                │
│      - extension whitelist: pdf, csv, json, txt         │
│      - MIME cross-check (non-fatal mismatch warning)    │
│      - size ≤ 50 MB                                     │
│      - filename non-empty                               │
│      - content non-empty                                │
│                                                         │
│   2. save → backend/uploads/{uuid}_{safe_filename}      │
│      (UUID prefix prevents path traversal / collisions) │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│   process_ingestion() [ingestion/service.py]            │
│                                                         │
│   STEP 1: Create IngestionJob (status=QUEUED)           │
│           → PostgreSQL commit (job ID established)      │
│                                                         │
│   STEP 2: Parse (status=PROCESSING → PARSED)            │
│           PARSER_MAP[file_type](file_path)              │
│           ├── pdf  → pypdf.PdfReader                    │
│           ├── csv  → csv.DictReader                     │
│           ├── json → json.loads (obj + array)           │
│           └── txt  → Path.read_text(utf-8)              │
│           Output: ParsedDocument                        │
│           ├── pages: List[ParsedPage]                   │
│           │    ├── page_number (provenance)             │
│           │    ├── text                                 │
│           │    └── metadata {fields, record_index}      │
│           ├── raw_text (concatenated)                   │
│           ├── record_count                              │
│           └── metadata                                  │
│                                                         │
│   STEP 3: NLP Extraction (status=EXTRACTED)             │
│           extract_entities(page.text) per page          │
│           ├── spaCy en_core_web_sm NER                  │
│           │    └── PERSON, ORG, GPE, LOC, DATE          │
│           └── Regex patterns                            │
│                └── PHONE (Indian 10-digit + +91)        │
│                └── VEHICLE (Indian registration KA01AB1234)│
│           → List[EntityCandidate] with provenance:      │
│                raw_text, normalized_value               │
│                source_page / source_row                 │
│                start_offset / end_offset                │
│                extraction_method                        │
│                                                         │
│   STEP 4: Structured field extraction (CSV / JSON only) │
│           _extract_structured_fields(page.metadata)     │
│           Maps field names → entity types via           │
│           STRUCTURED_FIELD_MAP lookup                   │
│           extraction_method = "structured_field"        │
│                                                         │
│   STEP 5: Entity Resolution                             │
│           resolve_candidate(db, candidate) per entity   │
│           ├── Finds matching CanonicalEntity by         │
│           │    fuzzy name + type                        │
│           ├── Creates new CanonicalEntity if no match   │
│           ├── Sets candidate.resolved_to_id             │
│           └── candidate.resolution_status               │
│                                                         │
│   STEP 6: Relationship Extraction                       │
│           extract_relationships_for_page(db, job, page) │
│           ├── STRUCTURED: CDR caller↔callee             │
│           ├── NLP TRIGGER: proximity-based co-mention   │
│           └── Writes EntityRelationship rows            │
│                                                         │
│   STEP 7: Finalize (status=COMPLETED)                   │
│           job.entity_count = len(all_candidates)        │
│           job.completed_at = now()                      │
│           → PostgreSQL commit (final)                   │
└─────────────────────────────────────────────────────────┘
        │
        ▼ (async, best-effort, non-blocking to PostgreSQL)
┌─────────────────────────────────────────────────────────┐
│   Neo4j Synchronization (projection layer)              │
│                                                         │
│   sync_canonical_entity(entity)  ← from resolution     │
│   _sync_to_neo4j(relationship)   ← from rel extractor  │
│                                                         │
│   ⚠ Failure is silent: exception caught + logged.       │
│   PostgreSQL data remains intact if Neo4j unavailable.  │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│   PHASE 3 BOUNDARY (NOT IMPLEMENTED IN PHASE 2)         │
│                                                         │
│   app/ai/workflows/fir_extraction.py                    │
│   → LangGraph workflow stub                             │
│   → LLM call is mocked (returns hardcoded text)         │
│   → NOT connected to the ingestion pipeline above       │
│   → Separate code path, Phase 3 responsibility          │
└─────────────────────────────────────────────────────────┘
```

## Database Schema

### `ingestion_jobs`
```sql
id              UUID PK
file_name       VARCHAR(500)
source_type     VARCHAR(50)   -- FIR, CDR, FINANCIAL_TRANSACTION, etc.
file_type       VARCHAR(10)   -- pdf, csv, json, txt
file_size_bytes INTEGER
status          VARCHAR(20)   -- QUEUED | PROCESSING | PARSED | EXTRACTED | COMPLETED | FAILED
error_message   TEXT
record_count    INTEGER
entity_count    INTEGER
uploaded_by     UUID FK → users.id
started_at      TIMESTAMPTZ
completed_at    TIMESTAMPTZ
created_at      TIMESTAMPTZ
updated_at      TIMESTAMPTZ
is_deleted      BOOLEAN
```

### `entity_candidates`
```sql
id                  UUID PK
ingestion_job_id    UUID FK → ingestion_jobs.id (CASCADE DELETE)
entity_type         VARCHAR(50)   -- PERSON, PHONE, VEHICLE, LOCATION, DATE, ORGANIZATION
raw_text            TEXT
normalized_value    TEXT
confidence          FLOAT
source_page         INTEGER       -- PDF: page number
source_row          INTEGER       -- CSV/JSON: row / record index
start_offset        INTEGER       -- character offset in document
end_offset          INTEGER
extraction_method   VARCHAR(50)   -- spacy_ner | regex | structured_field
resolution_status   VARCHAR(20)
resolution_score    FLOAT
resolved_to_id      UUID FK → canonical_entities.id
created_at          TIMESTAMPTZ
```

### `canonical_entities`
```sql
id          UUID PK
entity_type VARCHAR(50)
name        VARCHAR(1000)
aliases     JSONB
attributes  JSONB
created_at  TIMESTAMPTZ
updated_at  TIMESTAMPTZ
is_deleted  BOOLEAN
```

### `entity_relationships`
```sql
id                  UUID PK
source_entity_id    UUID FK → canonical_entities.id
target_entity_id    UUID FK → canonical_entities.id
relationship_type   VARCHAR(100)
confidence          FLOAT
extraction_method   VARCHAR(50)
ingestion_job_id    UUID FK → ingestion_jobs.id
source_page         INTEGER
source_row          INTEGER
event_timestamp     TIMESTAMPTZ
UNIQUE (source_entity_id, target_entity_id, relationship_type, ingestion_job_id, source_page, source_row, event_timestamp)
```

## Error Handling

| Failure Point | Behavior |
|---------------|----------|
| Invalid file extension | 422 Unprocessable Entity, user-facing message |
| Empty file | 422 Unprocessable Entity |
| File too large (>50 MB) | 422 Unprocessable Entity |
| Disk write failure | 500, generic message, details logged only |
| Parse error | Job status = FAILED, error_message stored |
| NLP error | Job status = FAILED, error_message stored |
| DB commit error | Job status = FAILED, error_message stored |
| Neo4j unavailable | Silent warning, job still COMPLETED in PostgreSQL |
| Scanned PDF (image-only) | Parse error raised → job FAILED with clear message |

## Security Controls

| Control | Implementation |
|---------|---------------|
| JWT authentication | `Depends(get_current_active_user)` on all endpoints |
| File size limit | 50 MB enforced in `validate_file()` |
| Extension whitelist | Only pdf, csv, json, txt |
| UUID-safe filenames | `uuid4().hex + "_" + original` |
| No path exposure | `file_path` is server-side only; never returned to client |
| No executable uploads | `.exe`, `.py`, `.sh` not in whitelist |
| MIME mismatch | Logged as warning, extension takes precedence |
| Error sanitization | Generic 500 to client; full traceback server-side only |
